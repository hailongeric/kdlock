# Real kernel API contention

This runner measures actual syscalls on private kernel objects: extended
attributes, file-lock queries, descriptor flags, pipe metadata, file positions
and UTS namespace names.
Userspace and surrounding security/result-copy paths remain in the measured
operation. A scoped ftrace module substitutes selected functions for the bound
object. Spin, mutex or reader/writer backends are selected at build time. The
`stock` arm runs the original kernel functions without a substitution module.

The historical [2026-10-11 results report](../results/10.176.26.71/bench/real_api/20261011/RESULTS.md)
contains 288 accepted, drained OFD/setfd sessions: four backends, three rounds,
two metadata layouts and six worker counts per API. It introduces each test
subject and kernel lock, relates the workload choices to the TCLocks paper, and
reports scaling, useful KD regimes, regressions and xattr admission limits.
The separate [run record](../results/10.176.26.71/bench/real_api/20261011/README.md)
retains reproduction commands, validation, exploratory failures and raw evidence.

These are API microbenchmarks with real kernel metadata, not end-to-end
application measurements or a global replacement of Linux locks. Neither loading
KD nor loading TCLock alone changes ordinary syscall locking.

The current compact-mutex result is the [pipebytes, pipecap and seek screen](../results/10.176.26.71/bench/mutex32-api-screen-20261019/README.md):
144 valid, drained sessions with fresh Native/TCLock controls. Pipe KD uses
local physical locking without measured JIT; contended seek returns JIT bodies.
The report keeps these categories, repeat variation and one final diagnostic-row
gap explicit. The historical [256-byte KD-only pipebytes comparison](../results/10.176.26.71/bench/comparison/mutex-kdonly-20261017T140354Z/README.md)
retains its original source and measurements.
The [workload catalog](../../docs/BENCHMARK_WORKLOADS.md) defines each label.
Broader historical API coverage retains its original adapter/provider identity;
it is not validation of every current KD mutex scenario.
All seven implemented adapters already call KD APIs. The catalog's
[API and delegation table](../../docs/BENCHMARK_WORKLOADS.md#kd-api-use-and-delegation)
distinguishes eligible bodies, local readers and unresolved translation refusals.

Xattr keeps the original list traversal, `strcmp()` calls and real `memcpy()`
value copy. The original `strcmp` uses the API contract introduced in version 10, which
models its read-only effect. It does not inspect helper code or scan the strings;
the syscall and selected source lock provide the same valid, stable storage
required by the native API. The reviewed caller also promises that ordinary
data accesses do not inspect or overwrite the `strcmp` service's temporary
CALL return-address storage.
Analysis records that control storage separately from ordinary object data and
refuses explicit known observers, while preserving original CALL writes and
traversal loads. This promise concerns the selected caller, not arbitrary kernel
code. `memcpy` remains a learned helper without a new writing-service summary.
Its CALL return word and RET use ordinary conservative analysis, and all copy
reads and writes remain present. There is no special copy-call classification or
return path. The generic refinement for partially overlapping CALL-return bytes
is archived; the maintained revision separates control storage only for the two
original string services. Focused unit and live correctness checks passed, as
recorded in the
[version 10 development record](../results/10.176.26.71/bench/taskname-xattr-native-api-20261019/DEVELOPMENT.md).
Ordinary address/context admission and common owner/frame/return checks
remain active. See the
[API contract](../../docs/design/admission.md#original-strcmp-service).

## Candidate selection

| Workload | Actual critical section and cached state | Suitability |
| --- | --- | --- |
| tmpfs `fgetxattr()` | `simple_xattr_get()` holds `simple_xattrs.lock` across linked-list name comparisons and the value copy | Implemented; many callers query one metadata-rich file. Attribute count and hit position control real search work. |
| `fcntl(F_OFD_GETLK)` | `posix_test_lock()` holds `file_lock_context.flc_lock` while checking owners, ranges and conflict type, then copying the conflict | Implemented for local, non-expiring OFD locks; models repeated byte-range conflict queries on one file. |
| `fcntl(F_SETFD)` | `set_close_on_exec()` holds `files_struct.file_lock` across the close-on-exec bitmap update | Implemented; each thread toggles its own preallocated descriptor flag in the shared table. Descriptor spacing changes the dirty bitmap footprint. |
| `ioctl(FIONREAD)` on a shared pipe | `pipe_ioctl()` holds `pipe_inode_info.mutex` while summing real buffer lengths around the ring | Implemented mutex case; occupied buffer count controls protected traversal, with one independent file description per worker. |
| `fcntl(F_GETPIPE_SZ)` | `pipe_fcntl()` holds the same pipe mutex while reading `max_usage` | Implemented short mutex control on the same real subsystem. |
| Shared-file `lseek(SEEK_SET/SEEK_END)` | `ksys_lseek()` holds `file.f_pos_lock` across size checks and `f_pos`/`f_version` updates | Implemented mutex case for an anonymous tmpfs file and one shared open description. |
| `uname()` with `sethostname()` / `setdomainname()` | `uts_sem` protects the real UTS structure: readers copy it, writers replace one name | Implemented bounded read/write experiment in a private UTS namespace; Native rwsem versus KD/TCLock reader/writer spinlocks, with the specialization below. |
| FxMark directory enumeration / rename | Shared dentry/rename state and, for cross-directory rename, `s_vfs_rename_mutex` | Candidate for wider integration; additional lock sites and filesystem behavior must be preserved. |
| will-it-scale `lock1` | Repeated `F_SETLKW` / unlock, with a **separate file per worker** | Useful reference; it does not itself create a shared inode lock. The original paper's kernel/version bottleneck must be re-established on this kernel. |
| will-it-scale `mmap1` | `mm_struct.mmap_lock`, a sleeping rwsem, covers VMA allocation/removal and potentially blocking/nested work | The local TCLocks copy maps and unmaps 128 MiB. [KD rwsem](../../docs/design/rwsem_implementation.md) supports explicit outer writer delegation, but that pair cannot preserve mmap's killable waits and downgrade paths. Full mmap APIs and execution context remain unintegrated; no KD mmap comparison is implemented. |
| eventfd / epoll wakeup paths | Short queue/counter critical sections, often with IRQ exclusion | Poor initial fit for the present ordinary-task-context delegation ports. |

## Contract and comparison limits

The client creates an anonymous `memfd`, fills its `trusted.kdlock.*` attributes
(root is required; this guest has no tmpfs `user.*` handler) or establishes
nonadjacent one-byte OFD write locks, and then waits for the controller. The
module pins that file and rejects linked files and non-tmpfs objects. The OFD
variant also rejects lock-manager callbacks and non-OFD locks. Once bound,
**no participant may mutate metadata, change the OFD locks, or close their owner
until all workers have joined and the substitution module has been unloaded**.
The controlled client implements that ordering. Do not attach this experimental
module to an application with independent readers/writers or use it as a general
kernel lock adapter. Other native consumers of the same spinlock are outside
the supported experiment.

The setfd case holds a reference to the client's `files_struct` and scopes the
hook to that file table. It changes only flags of preallocated descriptors;
opening, closing or duplicating descriptors is forbidden while bound. Each
worker owns a distinct descriptor, alternates its `FD_CLOEXEC` bit, and checks
the result with `F_GETFD`. Thus one setfd operation includes **two syscalls**,
of which one takes the substituted lock. Other cases use one syscall per operation.
Each setfd descriptor has its own open file description, so the syscall's
`fdget_raw()`/`fdput()` does not contend on one shared `file.f_count` outside
the target lock. The earlier shared-description screen remains separate evidence.

The xattr search/copy body follows the guest implementation, changing its lock
calls. The OFD variant inlines the guest owner/overlap/conflict tests and conflict
field copies. Callback handling is specialized away only after the binding
check establishes that the private locks have no callbacks. Native/TCLock/KD
receive the same body and data layout, without UBSAN in the workload. The
`stock` control exposes combined substitution/compiler differences; it is not
pooled with the matched native arm. The captured kernel has UBSAN enabled, while
all timed replacement/provider modules have UBSAN disabled. Therefore only the
matched native comparison isolates the lock change within this compiled body.

For xattr, `--entries N` installs N attributes, and `--value-size 64` gives each
attribute a 64-byte value. `front` finds the most recently inserted record in
one name comparison; `tail` finds the oldest record after N comparisons and
copies its value. `miss` makes N comparisons and returns `ENODATA` without a
copy. `size` searches for that same tail record with `NULL, 0`, returning the
length without a value copy. The main n16/n128 tail comparison therefore
contains both name search and the actual 64-byte `memcpy`; it is not a
size-query benchmark. At n128, exactly 128 `strcmp` calls fit their separate
per-body allowance. Other helper/control continuations retain the ordinary
allowance of 16.

Only one fixed worker runs on each selected CPU. The spin adapters operate on
the real lists or descriptor bitmap and original spinlock storage under the
controlled-consumer restrictions above. KD/TCLock mutex adapters and all matched
UTS adapters use private objects; Native mutex keeps the original lock, as
described below. Syscalls run individually, without an
ioctl loop or artificial arithmetic inside the critical section. Warmup and
setup are outside timing. User-buffer validation is inside timing and identical
across backends. Values differ by attribute key; every returned byte is checked.
The additional pre/post oracle checks all entries, size queries, `ERANGE`,
`ENODATA`, conflict fields, unoccupied ranges and same-owner non-conflicts.

The worker progress batch is 256 operations. The collector samples every 10 ms
on its own CPU; peak selection reuses the maintained full-cohort 300 ms window
validator after 300 ms of settling. `kernel_finished_ns` in its input schema is
the userspace timestamp after the last syscall returns, not a kernel probe.
All workers must make progress in the selected window. Both full-run throughput
and the highest valid peak are retained, together with CPU time and worker shares.

KD must publish an admitted translation before measurement. Xattr helper-learning
waves pause the daemon, join every caller, then resume translation; a refusal
ends that session. Each published image is saved before the next learning wave.
Preparation succeeds only after a wave returns a complete delegated body while
the entry remains admitted. Publication alone, or entering generated code before
falling back, is insufficient.

`--helper-workers 8` selects a separate, bounded preparation cohort from the
configured CPU list. It uses the same bound file and metadata as timing, including
when the measured cohort has only one worker. Every preparation caller finishes
before the next translation; the measured CPU list is unchanged. The runner
records each preparation cohort and its entry and completion counts. The daemon
then stops before the common warmup on the measured CPUs. `--helper-waves 0`
disables learning for an explicitly labelled initial-image diagnostic.

New records enable the completion probe and separate entry counts from complete
returned bodies. `PASS` means at least one complete body returned; `PARTIAL_JIT`
means code was entered but no complete body returned; `NO_JIT` means there were
no entries. Reports never pool these groups. Historical entry-only records keep
completion counts unrecorded. `--require-jit` requires a returned body during
every multithreaded KD measurement; single-worker timing need not delegate.
Immediately before and after measurement, the runner checks a drained publication
with zero translator writers and verifies that the prepared entry and generated
image hashes are unchanged. These boundary checks are outside syscall timing;
they establish image identity, separately from returned-body evidence.
TCLock spin delegation remains unmeasured, as in the existing comparator.
The module counts redirected calls, and the runner requires one call per
measured operation. A failed/undrained session has no accepted score.

## Mutex and reader/writer contracts

The [mutex module](../../workload_modules/real_api/mutex.c) keeps the real pipe
mutex or `f_pos_lock` only for Native. KD uses a private `struct kd_mutex` and
TCLock its private ordinary-mutex object; neither can share exclusion with an
unconverted Linux caller. This is a controlled adapter for the exclusively KD
assumption, not global replacement in the running kernel. The client creates an
unlinked FIFO, fills whole pages before binding,
and opens an independent description per worker. No pipe reads, writes or resizes
occur while bound. The seek case retains a shared description, restricts calls
to `SEEK_SET`/`SEEK_END`, and changes the real position on every worker's sequence.
Its surrounding shared `file.f_count` traffic remains part of the operation.

TCLock mutex workers register a fixed-CPU context before each phase. The client
joins every thread and retries the provider's checked drain for up to five seconds:
`pthread_join` can observe thread completion before the final kernel task exit.
No live-task or queue check is bypassed. `/dev/real_api_control` carries registration
and drain commands outside timing. Close it before unloading the source, while
retaining the benchmark object's descriptors until afterward.

The [UTS module](../../workload_modules/real_api/uts.c) binds only a private
`CLONE_NEWUTS` namespace with native x86-64 personality. Reads use `uname`; writes
set a 64-byte hostname or domain name. Every read checks for a complete allowed
name and unchanged other fields. User copies, permission checks, entropy mixing
and one proc notification remain in each syscall. The matched arms move that
notification after unlock, on the original caller. No proc-sysctl observers,
namespace changes or independent users of the bound namespace are permitted.

All three matched UTS backends use a private lock for the bound namespace: a Linux
rwsem for Native, and reader/writer spinlocks for KD and TCLock. This is a scoped
adaptation of the bounded, non-sleeping copy/update body, not a general replacement
of Linux rwsems. Stock retains global `uts_sem`, the original notification placement
and kernel instrumentation; its comparison includes all three differences. Global
proc notifications to other namespaces are retained in every arm. KD prepares the
ABI3 writer entry; readers execute locally through `kd_read_lock()` and
`kd_read_unlock()` with concurrent shared access. JIT shares use the number of
**writes**, not total mixed operations.
TCLock mutex delegation counts are recorded; spin/rwlock shares remain unmeasured.

the current kernel, NUMA placement and physical vCPU pins, and confirm a fresh
monitor snapshot of the actual CPU topology. Do not rebuild the kernel. The
standard guest has 64 vCPUs; collector 63 is excluded from worker cohorts.

`--value-size` defaults to 64 bytes. `--cpus` takes an ordered comma-separated
list, whose prefix defines each cohort. Use explicit interleaved NUMA placement
for a separate placement study. Do not pool different placements, payload sizes,
source versions, governors or warmup settings. `--build-from RUN` reuses saved
binaries only when all current source hashes and the previous binary hashes
match, and the requested mutex placement must match. The output retains all
planned sessions, including failures and unrun cases; the backend order rotates
between rounds.
The planner rejects duplicate thread counts, backends, workload kinds, queries
and entry counts so distinct requests cannot overwrite one session directory.
API runs retain the 63-worker maximum and a dedicated collector.

`--mutex-lock-offset {0,32,40,56}` is a separate KD mutex placement diagnostic.
It requires `--backends kdlock` and pipe or seek workloads. Each diagnostic
build places the unchanged 32-byte, 8-byte-aligned mutex at the requested byte
offset inside dedicated, 64-byte-aligned, 128-byte storage. Padding excludes
neighboring globals from both lines. Offset 0 or 32 keeps owner, gate and tail
on one line; offsets 40 and 56 put owner on the first line and gate/tail on the
second. The timed wrappers retain direct addressing. The runner verifies the
module's compiled offset and loaded address and records both. These records
are marked diagnostic and excluded from ordinary report scores; distinct
offsets cannot be pooled. Omitting the option preserves the original object
declaration and its natural linker placement. This changes only benchmark
storage, not the public mutex alignment or caller requirements.

New records bind the frozen source manifest, captured kernel identity and topology
to SHA-256 identities. KD mutex records explicitly name `kd-only-legacy`, ABI2
and the clobber caller. Reports separate source, protocol, caller, placement,
timing and instrumentation identities; the compact comparison refuses mixed
identities that would hide multiple implementations in one backend column or
across its worker counts. Missing historical fields stay `unrecorded`, without
assuming the current protocol. PMU/sampled diagnostic records remain unscored.
This restores reporting safeguards; no new benchmark outcome is implied.

Warmup requires at least 48,000 operations **and one second per worker** by
default; measurement is two seconds. `--warmup` and `--warmup-ms` control those
minimums. Shorter warmups belong in explicitly labelled exploratory screens.
No performance advantage is assumed or forced by the runner. Select promising
real workloads using retained exploratory evidence, then run three matched
rounds; report regressions and single-thread overhead alongside gains.

Join workers → verify data and protocol drain → retire KD sources → unload
substitution module → unload provider → close query/owner files. A timeout or
kernel fault retains the processes/modules for diagnosis; do not force unload.
Archive evidence before snapshot recovery. Live output belongs outside the
guest checkout, and host archives/reports follow the existing machine-specific
[result layout](../results/README.md).
