# 2026-09-17：单份 request、热状态与锁侧 WWJUMP

**四个配置、16/16 会话通过。** 相比[上一版三项优化](20260917-batch.md)，
20 线程的 1/16 cacheline 最佳吞吐达到 **1.550/1.519 Mops/s**，提高
**19.3%/18.2%**。4 线程提高 **7.6%/12.2%**。8 个 kdlock 会话均实际进入
批次入口，累计 **8,392,785 次 WWJUMP**；不是仅存在未使用的代码分支。

本轮以 `903d8a5` 的工作区为基础，保留已有 per-CPU 统计、批内 exe 复用和
下一请求预取，进一步将请求元数据移出可复用 node，普通 frame 只操作前
64 字节热状态，复杂 ledger/control/checkpoint 按需展开。锁侧驻留汇编每批
保存一次原始 combiner 寄存器，C step 自身的 ABI 保存仍逐请求发生。
专用 step 完成当前请求后准入下一请求；JIT 只执行
当前临界区。精确的最终 unlock 使用 callee-saved 与 RIP/SP、RDI 回写，
hostcall、CALL miss、native 和拒绝仍完整保存所支持的 GPR。ticket 只扫描
occupied 位图，普通单锁最终归还 request 用 release store；共享生命周期及
owner/ACK 所需原子操作、guard 保留。路径见[执行说明](../EXECUTION_PATHS.md#jit)。

每线程 100,000 次，1/16 cacheline × 4/20 线程，每点两对原生/kdlock 会话，
顺序原生→kdlock、kdlock→原生。CPU 0–19 同属 NUMA 0，沿用四组锁外乘加，
`bench_quiet=1 jit_timing=0`。未运行完整矩阵或跨 NUMA benchmark。

吞吐单位为全部线程合计的百万次完整操作/秒，包含锁外计算；保留各组最佳值、
中位数和最佳会话 JIT 比例。涨幅按两版 kdlock 的最佳值计算：

20 线程吞吐分别为本轮原生中位数的 **48.4%/77.9%**。这是本次合并改动的定向
结果，原生组为 Linux qspinlock，没有逐项消融，也没有运行 TCLock 对照。
每臂仅两次采样，宿主物理核独占
和频率未控制，不能据此宣称普遍收益或统计显著性。

共 **19,200,000 次操作**，测量期实际 JIT **8,829,348 次**，与批次入口计数
总和一致；最长测量会话 **1.353 秒**。每个 kdlock 会话均有正 WWJUMP 计数，
20 线程每场约 199.4 万次。计数是排空后汇总的观察值，不参与调度。

guest 为既有 `6.1.159-kdstatic2`，Build ID
`460d77502af4709a0cca794b322cedc20c2cc478`，voluntary、nokaslr，恢复快照
`pre_static_boot_20260915` 经 monitor 确认。负载源码与上版相同；本次测量期间
源码、四个二进制和 boot ID 不变，模块/已知调用者排空，未发现内核 fault，
watchdog 保持开启。宿主只读复核 196 个冻结输入、4 个二进制、24 个 JIT 映像

```sh
cd /root/host_fs/kdlock
LC_ALL=C KDIR=/root/linux-6.1.159-kdstatic2 KDLOCK_RECOVERY_CONFIRMED=1 \
KDLOCK_SNAPSHOT_TAG=pre_static_boot_20260915 timeout --kill-after=10s 1200s \
  python3 bench/spin_cacheline/run.py \
  --kernel-source /root/linux-6.1.159-kdstatic2 \
  --kernel-baseline /root/kdlock-kernel-baselines/spin-static2-20260915 \
  --cachelines 1 16 --threads 4 20 --cpus 0-19 \
  --iterations 100000 --repeats 2 \
  --output /root/kdlock-evidence/wwjump-20260917/bench
```
