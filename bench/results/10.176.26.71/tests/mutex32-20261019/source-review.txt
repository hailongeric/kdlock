Source-only final review: compact KD mutex

Scope: independent static review on 380G10. No source edits, builds, tests, VM
commands or running-input changes were performed for this final review.

Finding: no blocking correctness defect identified in the reviewed storage and
reference-lifetime changes. This statement is a source review, not runtime proof.

Geometry and interfaces
- include/kd_mutex.h keeps owner, wait_lock, osq and wait_list inline, in native
  order. kernel_module/mutex/lifecycle.inc asserts size 32, native alignment and
  every physical-field offset against the captured native struct mutex.
- node->aux occupies previously unused identity padding before regs at128; the
  existing 320-byte node size, regs128 and completion304/locked305 checks remain.
- include/kd_mutex_aux.h isolates executor/gate, tail and exact waiter count at
  offsets64/72,128,192. The256-byte side record is allocated from a cache requesting
  the type's128-byte alignment. Public object alignment is unaffected.
- workload_modules/mutex_cacheline/module.c gives only the standalone benchmark
  variable explicit64-byte alignment. runner.inc now compares type size and type
  alignment to native while separately asserting the variable's cacheline alignment.
  This preserves deliberate workload separation without imposing64-byte alignment
  on callers' embedded KD mutex objects.
- The exported combiner observation remains a pre-acquisition root-shell CALL.
  It is outside the post-lock ABI2 entry; nested supported DIRECT calls are handled
  as whole control calls. Nested OUTER usage remains refused by existing admission.

Concurrent registry
- Lookup/reference acquisition and final unlink use the same per-address bucket
  raw spinlock. A referenced pointer never depends on a lockless hash traversal.
- Allocation is outside the bucket lock. The locked duplicate recheck installs
  only one record per address and frees losing candidates after releasing the lock.
- Each last put requires zero executor, gate/state, tail and exact waiter count,
  unlinks under the bucket lock, then frees. This permits immediate address reuse
  after all callers have finished, without a caller destroy/cleanup requirement.
- is_idle rejects any live record even when its queue fields are zero. Global
  idle scans exact membership, not an approximate aggregate. These observations
  retain the documented stopped/joined-caller prerequisite.
- Allocation refusal occurs before publication and releases the task-routing ref
  before using the existing inline KD physical lock. It does not mix Linux locking.

Reference paths
- _kd_mutex_lock_abi obtains INVOCATION before gate or queue access. Thus even the
  tail-exchange to waiter-count-increment interval has a live record reference.
- claim_origin adds OWNER while INVOCATION protects the record, before sleeping
  for physical exclusion. Normal physical C returns drop INVOCATION; OWNER survives.
- _unlock_checked obtains a temporary lookup ref, clears executor, releases physical
  mutex, release-stores gate0, then drops OWNER and lookup refs. A new claimant
  after gate release cannot invalidate those remaining references.
- Every completed producer copies its needed packet and retires its node before
  INVOCATION is dropped. Clobber completion obtains aux from node->aux because
  the original C frame may have been overwritten, then resumes outside that frame.
- Native handoff may retire the producer's node and INVOCATION before ACK. The
  executor's enclosing INVOCATION still spans synchronous native_wait, final ACK,
  frame completion/pop, and return from the combiner.
- Early release_outer drops OWNER but retains the enclosing INVOCATION while B,
  the frame and ACK can remain live. Reacquiring A adds a new OWNER reference.
- Nested physical locks do not need delegation records. Their exact lock ledger,
  native request/ACK handling and source leases remain intact.
- Cache creation precedes publication; initialization failures and drained teardown
  destroy the auxiliary cache after checking exact membership.

rwsem source-derived layout (requires later compiler/DWARF confirmation)
include/kd_rwsem.h:13-20 retains gate at0; gate now occupies32bytes/alignment8.
The independently aligned fields imply readers64, admission128, phase_wait192,
reader_drain256. Under the captured non-debug x86-64 wait_queue_head_t geometry
(24bytes/alignment8), the end is280, rounded to overall alignment64: size320.
No member retains the former gate's128-byte alignment. Thus expected kd_rwsem
is320bytes/alignment64, not a claim that it matches native rw_semaphore geometry.

Validation boundary
Root reports2 basic plus12 affected checks, local mutex live probe and rwsem live
probe passed. This reviewer did not independently execute or inspect those runs.
Returned-JIT retry and native instruction-exit live validation were still running
when this review was requested; this review makes no pass claim for them. The
initial returned-JIT build's stale256-byte workload assertion was a compile failure,
not a test pass; the reviewed native-geometry assertion is its correction.
No performance gain is inferred. Side allocation, registry bucket locking and
compact-object cacheline placement may change costs and need separate measurements.
