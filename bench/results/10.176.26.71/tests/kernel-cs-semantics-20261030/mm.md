## mmap and munmap: actual critical-section ranges

VERIFIED syscall route: `K/mm/mmap.c:567–610` (`ksys_mmap_pgoff`) invokes `vm_mmap_pgoff`; anonymous mappings skip file acquisition. `K/mm/util.c:565–588` gets `current->mm`, performs security/fsnotify checks **before** locking, takes `mmap_write_lock_killable`579, calls `do_mmap`581, then write-unlocks583. Userfault completion584 and optional `mm_populate`585–586 are **after** release. The initial killable API and its failure semantics are part of the selected mmap operation, not a rare helper branch.

Inside that writer interval, `do_mmap` (`K/mm/mmap.c:335–564`) validates flags/ranges, selects an address through `__get_unmapped_area`407 and invokes `mmap_region`559. `__mmap_region` (`K/mm/vma.c:2729–2800`) gets `current->mm`, performs setup, tries adjacent-VMA merge2759–2764, otherwise allocates a VMA2767–2771, and completes tree/accounting updates2777. File `mmap_prepare`/actions2751/2779, executable protection key work (`mmap.c:391`), MAP_LOCKED/populate, fixed-address replacement/unmapping and userfault-related work are conditional. They must not be charged to every anonymous untouched mapping. VMA allocation, maple allocation, merge and per-VMA write exclusion can nevertheless introduce nested calls or waits on actual branches; no allocation or sleep is proven absent from every mmap1 iteration.

VERIFIED munmap route: syscall `K/mm/mmap.c:1075–1078` passes `unlock=true` to `__vm_munmap`. `K/mm/vma.c:3259–3275` gets `current->mm`, takes a **killable writer**3266, calls `do_vmi_munmap`3269 and explicitly write-unlocks only on error or `!unlock`. `do_vmi_munmap:1611–1634` returns an invalid-range error with ownership retained, or write-unlocks a successful empty-range case1627–1629. The mapped-range path isolates/detaches VMAs and reaches `vms_complete_munmap_vmas:1311–1350`: counts are updated1317–1319, then the successful syscall path **downgrades writer to reader**1320–1321; page-table cleanup1326 and remaining accounting/close/free run before `mmap_read_unlock`1347. `vms_clear_ptes:1256–1285` explains why isolated VMAs permit cleanup under read ownership. There is no simple unconditional writer-unlock endpoint for this syscall.

INFERRED integration consequence: current rwsem rules (`R/include/kd_rwsem_api.h:9–12,50–61`) keep killable/callable/cleanup acquisitions local and preserve downgrade. A prepared ordinary macro writer's no-downgrade/lexical promise cannot be applied to these unchanged mmap1 syscall paths, nor can changing a killable call to ordinary down-write be described as a lock-only semantic-preserving substitution. The existing local MM backend preserves these paths and is the applicable supported comparison. For an independently eligible ordinary writer elsewhere, branch-specific translated prefixes/native suffixes are a separate question; the existence of a sleeping or flush branch does not prove the entire prefix impossible.

Untouched mapping is not equivalent to “munmap can never inspect page tables.” Adjacent mappings/table lifetime, prior population, fixed replacement and concurrent users can affect the tree. `unmap_region` (`vma.c:473–488`) gathers TLB work, unmaps and frees tables, then finishes the gather. Empty PTEs are skipped (`memory.c:1828–1837`), and `tlb_flush_mmu_tlbonly` only calls the flush if cleared/freed/unshared flags are set (`E/include/asm-generic/tlb.h:495–506`). Thus a hardware TLB invalidation is **not a mandatory per-mmap1-operation instruction**; actual populated teardown has additional obligations.

## PTL critical sections: separate fresh install, update, replacement and teardown

The common `pte_offset_map_lock` (`K/mm/pgtable-generic.c:391–409`) maps under RCU, determines the exact table's lock, locks402 and **revalidates PMD**403; changes unlock/unmap and retry. `pte_unmap_unlock` (`include/linux/mm.h:3565–3568`) spin-unlocks first and then unmaps/drops RCU. Ordinary spin lock disables preemption before acquisition and unlock reenables after release (`spinlock_api_smp.h:154–169`); it does not imply IRQ-disable. Explicit IRQ variants have their own order and cannot be silently collapsed. A caller can have acquired an RCU/table lifetime before the lock helper returns; replacing only an inner acquire without preserving this outer lifetime is insufficient.

## Folio critical sections and ownership mismatch

VERIFIED `filemap_fault` (`K/mm/filemap.c:3513–3696`) looks up the folio, conditionally takes mapping invalidate-read lock/does readahead or allocation, then calls `lock_folio_maybe_drop_mmap`3576. That helper (`filemap.c:3265–3297`) first tries the folio bit lock; contention may drop mmap ownership, return retry, wait killably or wait normally. Once locked, filemap_fault rechecks mapping/truncation3580, uptodate state3592 and EOF3629. Successful page delivery3636–3637 returns **VM_FAULT_LOCKED**, transferring a locked folio to its caller; the read-fault caller finishes mapping and later unlocks (`memory.c:5829–5835`). I/O via `filemap_read_folio`3647 is a conditional not-uptodate path, not mandatory on cache hits.

`__folio_lock_or_retry` (`filemap.c:1754–1785`) has explicit coupled outer-lock semantics: first-retry NOWAIT leaves the outer lock held and returns retry1763; otherwise release_fault_lock1766 drops mmap or per-VMA ownership before waiting; killable failure1776–1779 also releases the outer lock. `folio_unlock` explicitly allows interrupt-context release1502. `folio_end_read:1530` participates in I/O completion. Waiting uses the bit-wait protocol (`__folio_lock:1703`, `folio_wait_bit_common`) rather than a same-task owner field.

INFERRED: ordinary KD mutex ownership and two-word root completion cannot simply replace PG_locked. A separate compatible bit-lock/lifetime protocol would be needed and is outside the authorized minimal-lock integration. This does **not** mean a cache-hit body is inherently unsuitable for instruction translation; it means the existing folio acquire/release protocol, cross-function return and asynchronous ownership must remain native and exact. For anonymous untouched mmap1, filemap/folio I/O is not on the declared mapping body at all.

## Whole-object participants and context requirements

VERIFIED mmap participant examples: brk (`K/mm/mmap.c:126–212`), fault/stack growth above, madvise read/write routing (`mm/madvise.c:1778–1808`), fork/dup_mmap's killable old-mm writer plus nested new-mm writer (`mm/mmap.c:1740–1747`) and killable per-VMA writes1766, and exit_mmap (`mmap.c:1275–1328`) with initial read phase1286–1303 followed by write phase1310–1327. Teardown explicitly permits preemption while holding only the now-unreachable mmap writer1317–1320. An object conversion cannot omit these participants or assume a single current-mm, lexical, ordinary-writer path. Other kernel users (including proc/GUP/mprotect/mremap) need the same protocol; their entire implementations were not in this capture and are not presented as freshly audited here.

BPF/non-owner is a concrete compatibility case, not a hypothetical warning. The exact maintained Linux7 patch (`R/kernel_integration/linux70/mmap-lock.patch:218–330`) shows stackmap and task_iter read-trylock callers and IRQ-work non-owner release. Enabled-MM policy reserves its per-CPU slot **before** acquisition/callbacks, cancels only its own empty reservation, and transfers an acquired share through a single-use token. Captured `K/mm/mmap_lock.c:575–590` does mmgrab before publishing token, consumes it with xchg-to-NULL, performs non-owner read release, then mmdrop_async. Disabled mode retains native raw-mm/lockdep/IRQ-work routing. The BPF .c/.h source bodies and their objects were not in the new pack; patch context and existing source-identity/fixture receipts are the evidence used here. Live BPF/IRQ/NMI remains explicitly unvalidated (`R/kernel_integration/linux70/MMAP.md:39–50,124`).

Context classification is per operation. Ordinary mmap bodies contain logical task/mm, security/accounting, allocations and conditionally callbacks; they do not all contain direct CR3/TLB instructions. Fault entry enables IRQs before outer acquisition (`fault.c:1279`), uses original fault registers/address/current mm and can modify task fault/memcg state. PTL intervals disable preemption but may have IRQs enabled; folio acquisition can sleep; remote TLB operations can send IPIs; local TLB helpers must use the actual CPU's loaded mm and ASID state. `files` lookup for file-backed mmap occurs before the mmap writer; anonymous mmap skips it. IRQ/preemption/mm state must not be inferred solely from a source function's name.

A concrete inline context transition exists before any hypothetical missing-callee escape: captured `mm/memory.o` `do_wp_page` at0x798a increments GS `__preempt_count`,0x7991 executes LOCK BTS of an internal bit lock,0x799d decrements preempt count on contention, and0x79a6–0x79b2 runs a PAUSE/test/retry loop. This matches `K/include/linux/bit_spinlock.h:38–46`; the successful path also eventually clears the bit and reenables preemption. This is distinct from the folio PG_locked sleepable bit and conditional within do_wp_page. Merely redirecting those GS accesses to waiter storage does not perform the native physical-executor preemption transition. An earlier exact native continuation, or separately validated context contract, would be necessary for that path; relying on a later CALL boundary is insufficient. Root/sibling also identified a source-only PAUSE preservation issue: captured F3 90 is decoded by the pinned Miasm path as prefixed NOP, while `R/disassem/special_inst.py:106–108` emits bare NOP. Their static finding is not an executed decoder test or proof a measured JIT took this MM path. The original native sites remain recorded in `/tmp/kdlock-semantic-native-pause-fences-20261030.json`.

The translator explicitly recognizes logical current-task and origin GS operands (`R/disassem/normal.py:1–2,42–81,191–201`), so a current/GS access alone is not a blanket refusal reason. Conversely, substituting logical current data does not switch executor CR3, perform scheduler operations on the correct running task, repair arbitrary RCU nesting, or make hardware TLB/cache/user-access effects transferable. The production source-trust policy bypasses semantic admission; it does not create missing backend support or prove these effects safe.

A supported ordinary CALL may end a translated prefix and move the exact remaining native suffix to the origin without replay; this potential must be checked against the emitted call/return graph, source/frame leases, physical owner and exact unlock routing. Explicit reviewed native instruction descriptors (`R/disassem/native_escape.py:34–59`) include CLI/STI but **not** INVLPG, INVPCID, INVLPGB, TLBSYNC, CR3 or STAC/CLAC. Thus “a later branch needs a flush/sleep” is not proof that no prefix can delegate, and “there is native escape” is not proof that every MM branch is supported. All currently maintained MM bodies still execute on the original task.
