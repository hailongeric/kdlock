# KD translation boundaries and execution context — source audit, 2026-10-30

This is an analysis record, not an implementation or validation result. **M** means maintained `24b7a80591a3c8367398cc7375ae0c5952069bfb`; **C** means unpromoted READY-first candidate `2dbcd7afbf141dd63dcf0086b65fd0da4b32d6f7`. Paths and line numbers below refer to M unless explicitly marked C. Source inspection found no diff between these commits in `disassem/`, `include/{wrapper.S,asm_head.h,kd_regs.h,kd_spin_direct.h,kd_spin_api.h}`, `kernel_module/spin/`, `kernel_module/exe.c`, or `kernel_module/execution/{control_calls,wrapper_entry}.inc`. Their translation, spin and instruction-exit conclusions therefore apply to both. Mutex origin scheduling/role transfer differs, as described below.

No builds, tests, translator execution or VM operations were performed for this audit. Reading existing native object disassembly does not validate generated KD code. Existing test source is cited only to identify coverage, not as a new pass. No TCLock implementation was consulted or used as evidence.

## Main conclusions

1. **Verified:** source conditional branches execute conditionally in generated code. A missing ordinary CALL or a supported instruction marker can end only the path that reaches it, retaining already executed effects. Fences and LOCK-prefixed atomics have direct lowering. **New source-level defect:** the captured decoder represents F3 90 as prefixed NOP, and KD's NOP special case drops its prefix, losing PAUSE rather than executing it or escaping.
2. **Verified limitation:** this is not a universal instruction-granular fallback. Whole-entry structural/text/backend failures remain; instruction, indirect-dispatch and branch-budget runtime errors are not general native continuations. A progressed body cannot simply restart natively.
3. **Verified limitation:** the first executed instruction marker disables the entire entry for future delegation. Current code does not permanently retain a hot translated path after a rare native-marker branch.
4. **Verified limitation:** waiter GS/task substitution is not a hardware-context switch. Explicit spin IRQ/BH pairs stay local. Plain-spin root admission excludes several contexts but does not compare saved waiter IF against executor IF, and has no general preempt/BH/IRQ state packet.
5. **Verified limitation:** unconverted Linux lock APIs are not silently mapped to KD object controls. However, after their first CALL-miss native suffix, trusted translation can learn their ordinary implementations. There is no permanent Native-lock boundary guaranteeing that later generations remain on the original task.

## 1. What is translated and where execution leaves it

| Source/runtime situation | Actual behavior | Source proof |
| --- | --- | --- |
| Ordinary conditional branch | Preserves the source branch and target; both reachable source alternatives participate in scope/decode. A branch merely containing an escape does not execute that escape on the other path. | `disassem/special_inst.py:78–100,187–210`; `translation_image.py:116–193` |
| Decoded ordinary callee | Lowers its actual instructions; virtual CALL pushes the real original continuation word, RET pops and dispatches it. | `special_inst.py:109–125`; `indirect_jump.py:18–90` |
| Missing direct ordinary callee | Emits CALL-miss exit at that target. The original waiter runs that callee **and the remaining native suffix**; this invocation does not return from native code to the JIT. Learning may change a future image. | `context_policy.py:50–103`; `indirect_jump.py:119–134`; `kernel_module/exe.c:617–640` |
| Known KD lock control CALL | Runtime services an exact saved CALL/acquisition and may resume at its continuation; specific unsupported cases use pending native continuation. It is not arbitrary function proxying. | `execution/control_calls.inc:32–52,208–352`; `lock/mixed_calls.inc:8–48` |
| Current scalar hostcall | `ktime_get`, `ktime_get_ns`, `int_sqrt` execute through declared runtime handlers; return value and CALL continuation are updated, then JIT can resume. | `disassem/hostcall.py:56–88`; `execution/hostcalls.inc:53–73`; `exe.c:504–533` |
| Exact supported instruction marker | Spill virtual GPR state, save arithmetic flags, exit **before** the original instruction, and resume on the original waiter at that exact source RIP. No fake CALL word is consumed. | `special_inst.py:30–41`; `execution/wrapper_entry.inc:146–248`; `spin/restore.inc:48–92` |
| Runtime unsupported instruction / branch budget / unlisted indirect target | Reports `KD_EXE_RUN_ERROR`, not `KD_EXE_RUN_NATIVE`. If a mutex or spin body has progressed, lock-side code invokes BUG rather than replaying it. | `exe.c:657–674`; `mutex/combiner.inc:404–407` (C:603–606); `spin/execute.inc:185–190` |

Current exact-byte instruction markers are `RDTSC`, `RDTSCP`, `CPUID`, `RDMSR`, `WRMSR`, `RDPMC`, `CLI`, `STI`, `CLD`, `STD`, `LAHF`, `SAHF` (`disassem/native_escape.py:34–60`). Their raw bytes, lack of explicit operands and decoded length must match. There is one exact RDTSCP decoder-alias repair (`native_escape.py:63–78`). The provider independently checks this opcode set (`wrapper_entry.inc:146–169`). This is not an arbitrary failed-instruction decoder.

**Important persistence limit:** `kd_jit_native_escape()` sets the native-escape tag, saves the continuation, and calls `kd_image_disable(exe)` (`wrapper_entry.inc:237–248`). `execution/images.inc:245–250` publishes `KD_EXE_NATIVE_ONLY`; the registry status update treats that state as sticky (`registry_lifecycle.inc:45–46`). Thus a cold marker branch can leave the hot path translated until the branch first executes; afterwards the entry is native-only for that registry lifetime. CALL-target learning has different behavior.

**Spin/root marker restriction:** ABI1 spin and ABI3 writer markers require the negotiated root capability and a special root image. The complete selected graph rejects learned/indirect/unresolved control, hostcall services and nested or nonterminal known lock controls (`disassem.py:207–218,268–283`; `native_escape.py:121–170`). Runtime additionally requires an untouched root packet at entry and exact one-lock root custody at escape (`wrapper_entry.inc:179–220,418–439`). These checks still run under trusted source. Mutex ABI2 markers have their own exact frame/borrow/stack/source checks, not this same root-only graph restriction.

**Cross-function root return:** a RET from the function containing the converted lock is not automatically a native suffix boundary. RET uses the generated indirect whitelist, whose targets come from decoded CALL relationships and learned history (`special_inst.py:122–125`; `indirect_jump.py:18–90,93–115`). An unknown actual root return becomes IJ error. `critical_section_blocks()` does not simply reject every root RET before an unlock (`context_policy.py:480–544`). Therefore a lock acquired in one function and released by an outer caller needs its exact source entry/return graph and execution evidence; a successful publication does not prove this path works. This matters for an API such as `fdget_pos` returning to a caller that later releases the position lock.

## 2. PAUSE, fences and atomic instructions

**Verified emitter behavior:** this backend decodes Miasm **assembly blocks**, then serializes source instructions to assembly. It does not lower these instructions through an optimizing Miasm semantic-IR pass (`translation_scope.py:152–177`; `translation_image.py:116–193`). Consequently an empty semantic IR for PAUSE/fences would not itself drop their machine instruction in this pipeline.

For decoded `LFENCE`, `MFENCE`, `SFENCE`, no escape descriptor or special dispatcher applies. `special_inst.translate()` reaches `process_normal()`, which emits `make_inst(name, operands)` (`special_inst.py:187–210`; `normal.py:119–159`; `assist.py:71–94`). Zero-operand forms need no operand-conflict expansion. The emitted source mnemonic remains in sequence, without a runtime service/exit per occurrence. The captured actual decoder registers these three forms at `miasm/arch/x86/arch.py:3793–3795`.

**PAUSE differs and needs correction before claiming preservation.** The captured installed decoder source is `/tmp/kdlock-semantic-decoder-20261030/miasm/arch/x86/arch.py`, SHA256 `95db31ba5cfa778102c31c2bf730f82f3a22c9fad8b97293717b180119a8f21b`; its capture receipt records the designated guest venv path. F3 is consumed as group-1 prefix value12 (`arch.py:778–807`), copied into the decoded instruction (`arch.py:895–898`); the NOP byte90 alias accepts no-REX forms without forbidding that F3 prefix (`arch.py:889–898,4085`). The explicit PAUSE registration is commented out (`arch.py:3911`). The captured decoder core `/tmp/kdlock-semantic-decoder-core-20261030/miasm/core/cpu.py`, SHA256 `3f8964158c69eee82f87cb471c9aef831b6299c21ca30f982f3015d0071c0d24`, constructs the instruction with its prefix metadata and full original bytes (`cpu.py:1273–1278`), and prefers an alias when multiple decode candidates exist (`cpu.py:1279–1294`). This closes the competing XCHG EAX,EAX candidate: the registered NOP alias wins. KD's `get_inst_name()` could spell this REP NOP (`assist.py:105–108`), but `special_inst_dispatch()` tests the original `line.name == "NOP"` and unconditionally writes bare `NOP\n` (`special_inst.py:103–108`). The PAUSE name in `instruction_policy.py:32` does not repair this actual decoder-alias path. This is a concrete static decoder/emitter defect, **not a Miasm empty-IR optimization**. No newly executed decoder/translator or emitted-byte test is claimed here. The appropriate narrow repair would recognize the exact PAUSE source encoding and preserve a physical PAUSE; a runtime handoff on every spin-loop iteration is unnecessary.

`assist.get_inst_name()` explicitly preserves the decoder's LOCK prefix (`assist.py:97–108`). Ordinary `LOCK ADD`, `LOCK XADD`, `LOCK CMPXCHG` therefore retain their hardware atomic operation on the lowered operand address; GPR/address rewriting and spill bookkeeping may surround them. `solve_bug.solve_cond_jmp_lock_cmpxchg()` is a narrow output/CFG workaround, not a replacement atomic service (`solve_bug.py:8–68`). `tests/unit/codegen/test_rip_relative_codegen.py:100` exercises a LOCK ADD assembly case; this is test-source evidence only.

The captured Linux 7 source confirms that these are real native primitives, not universally escapable overhead: `/tmp/kdlock-semantic-source-20261030/source/arch/x86/include/asm/barrier.h:22–24` emits MFENCE/LFENCE/SFENCE; line53 implements `__smp_mb()` as `lock addl` on stack memory; lines59–76 show release/acquire and before/after-atomic barriers can instead be compiler barriers/no added instruction on this target. `asm/cmpxchg.h:94–137` emits LOCK CMPXCHG. Existing `build/fs/file.o` contains, for example, LOCK ADD at `.text+0x2aa`, LOCK CMPXCHG at `+0x588`, LOCK XADD at `+0x7fa`. These object observations establish native instruction presence, not KD execution or their frequency in every chosen critical section.

**Which bodies need it:** the captured Linux7 `include/linux/bit_spinlock.h:38–46` executes `cpu_relax()` on every taken inner contention-loop iteration, between real preempt-enable/disable transitions. Existing `build/mm/memory.o` has an explicit example at `do_wp_page+0xfd6` (`.text+0x79a6`): `f3 90`, bit polling, then a backedge to PAUSE; the surrounding code changes `__preempt_count` and retries LOCK BTS. Native `kernel/locking/qspinlock.c:230–234` has the node-exhaustion polling loop; its pending/MCS/head waits are at152/291/328. Native `mutex.c:363–387` and `rwsem.c:770–785` include PAUSE-bearing optimistic ownership loops, conditional on contention and their scheduling checks. `arch/x86/mm/tlb.c:469–479` waits for a remote context switch with `cpu_relax()`; `build/arch/x86/mm/tlb.o` includes PAUSE in `flush_tlb_mm_range` at `.text+0x1809`.

The offline object scan `/tmp/kdlock-semantic-native-pause-fences-20261030.json` records exact object hashes and PAUSE sites, including `copy_page_range` and rmap helpers. It found no PAUSE instruction in the captured `fs/{file,pipe,locks,read_write,xattr,open}.o` bodies. That does **not** exclude their out-of-line lock/helper callees. A simple pipe/file query should not be described as unconditionally executing PAUSE; an inner contention path or MM bit-lock path is a different scope. These observations do not measure branch frequency or prove KD can execute all surrounding context transitions.

**Limit:** source/decoder inspection is not an assembled generated-image test. Representative F3 90 / fence / atomic byte tests remain appropriate, especially for the identified PAUSE loss. A general claim that every x86 encoding is faithfully lowered is unsupported. Trusted source bypasses the broad instruction-state policy and there are warning-only unresolved operand paths (`normal.py:162–212`); an unknown mnemonic is not automatically converted into a safe marker.

## 3. Rejection, build failure and native-only entry are different

Production defaults to `trusted_source=True` (`disassem.py:118–152`). It bypasses context-symbol screening, instruction safety policy, context/value analysis and minimal-entry input proof (`disassem.py:300–301,350–362,493–501`; `special_inst.py:187–200`). Tests using `render()` default to **checked** mode (`tests/unit/codegen/test_jit_diagnostics.py:64,137–160`); the many processor-state rejection tests cannot be cited as current production rejection policy.

Remaining verified whole-entry refusals include source lease/read limits, incomplete/overlarge CFG expansion, invalid lexical nesting, root-marker graph restrictions and incomplete/budgeted CALL/RET dispatch (`disassem.py:223–225,249–283,327–328,460–474,486–492`; `memread.py:41–83`; `indirect_jump.py:18–90`). Exact known FS/GS decoder misrepresentation raises even in trusted lowering (`special_inst.py:191–195`; `instruction_policy.py:60–69`). Backend exceptions or assembler failures raise rather than inventing a continuation (`disassem.py:65–70,531–566`). Decoding/return-graph work precedes marker-edge cutting, so merely placing a marker earlier in a source path does not currently waive all later source-decode requirements (`disassem.py:476–519`).

`reject_translation()` deletes stale output and returns the deliberate native-only exit2 (`disassem.py:57–62`). The daemon publishes native-only only for that result. Exceptions/signals/build/environment errors instead produce failure and no new upload (`daemon/workspace.inc:49–57`; `daemon/daemon.c:165–187`). A not-ready image hands an **unstarted** request back to native queue ownership (`mutex/combiner.inc:255–266`; `spin/entry.inc:142–149`). None of these outcomes is a successful translated prefix ending at the unsupported opcode.

## 4. What waiter state is carried, and what remains physical

**Verified packet:** `kd_regs` stores RIP/SP/BP, scalar GPRs and software flags/segment fields (`include/kd_regs.h:12–64`). ABI clobber entries initially import only their minimal continuation/stack contract; compiler spills define body inputs. The frame separately holds `gsbase` and `logical_task`, but no saved preempt count, softirq count, hardware IF, CR3/active-mm, FPU context or IRQ execution stack (`include/kd_exec.h:95–167`). Presence of a `flags` field is not an entry hardware-context snapshot: flags-aware markers explicitly populate it.

Spin publication records the waiter's task and GS base and prepares its minimal packet before publication (`spin/slowpath.inc:331–359`). The two wrapper argument words are precisely GS base and logical task (`execution/wrapper_entry.inc:480–493`; `include/asm_head.h:55–66`). Generated GS-relative memory becomes an ordinary address based on saved GS; a recognized 64-bit current-task MOV becomes the logical task value (`disassem/normal.py:42–49,191–205`). **No WRGSBASE/SWAPGS, scheduler context switch or hardware IRQ-state installation occurs.** Physical RSP/RBP are the combiner's wrapper stack; virtual source SP/BP address the waiter's stack (`include/wrapper.S:1–5,65–99`).

Plain public spin macros expose an **unpinned** clobber CALL before caller-state changes; the provider adds the native pin. Named DIRECT shells instead pin and read the CPU heat gate before their pinned CALL (`include/kd_spin_api.h:7–30`; `kd_spin_direct.h:59–90`; `spin/entry.inc:194–200`). Do not mix these call shells when reasoning about nested translation.

Plain spin root eligibility checks task context, softirq state, migration-disabled state and occupied execution context; before publishing a JIT request it requires `preempt_count()==1` (`spin/entry.inc:145–180`). Thus a previously preempt-disabled caller does not become an ordinary root proxy, and BH/interrupt roots route to native ownership. Tickets retain exact task/CPU/generation and a real preemption pin (`spin/ticket_origin.inc:52–112`; `include/kd_spin_entry.h:17–69`). Frame ownership validates executor/frame/ledger lifetimes; it is not a general comparison of saved scheduler/IRQ states (`execution/frame_lifecycle.inc:66–101`; `kd_exec.c:70–113`).

**Specific gap:** these plain-spin admission predicates have no `irqs_disabled()` check or waiter/executor IF comparison. Task context with IRQs already disabled can still have `preempt_count()==1` after the spin pin. Therefore do not infer interchangeable execution for arbitrary externally IRQ-disabled plain-spin callers. Explicit IRQ variants take a different path.

**Explicit IRQ/BH pairs are local:** `kd_spin_lock_irqsave/irq/bh` use non-combinable native ownership on the same KD word and preserve the target kernel's acquire/release context order (`include/kd_spin_direct.h:117–174`). Captured Linux7 `include/linux/spinlock_api_smp.h:125–159,172–196` confirms the corresponding IRQ-save→preempt-disable→lock and unlock→IRQ-restore→preempt-enable/BH-enable order. This is local behavior, not delegated IRQ-context emulation.

**Flags escape:** restore merges only `KD_REG_ARITHMETIC_FLAGS` (0x8d5) into the original waiter's current control flags. IF/DF/AC are intentionally not imported from the executor (`spin/restore.inc:48–92`; `include/kd_regs.h:39`). The original CLI/STI/CLD/STD then executes natively. This preserves a supported marker boundary, not arbitrary context-mutating instructions earlier in the JIT prefix.

**Inferred integration limit:** matching numeric preempt/IRQ state alone would not prove equivalent CPU-local exclusion. For example, rewriting a GS-relative preempt-count update to the waiter's CPU memory does not disable the executor's preemption. Captured Linux7 `arch/x86/include/asm/preempt.h:25–38,78–96` implements those counters through local CPU operations. Trusted-source policy does not introduce an inline preempt/BH/RCU/IRQ transition model. Explicit wrapper context semantics, or a native exit before such a transition, remains necessary for new real API scopes.

## 5. Converted outer lock with unconverted inner Linux locks

**Verified mapping:** runtime control addresses are KD-owned: `raw_spin_lock_addr = kd_spin_lock_legacy`, `mutex_lock_addr = kd_mutex_local_lock`, plus KD clobber/direct entry addresses (`execution/registry_lifecycle.inc:89–118`). The translator uses the same KD identities (`disassem.py:158–196`). Native `_raw_spin_lock`, `mutex_lock`, `down_read`, `down_write` are not automatically reinterpreted as KD controls on Native objects. The translator has a historical fallback to Native `_raw_spin_lock` only if the KD legacy symbol cannot be resolved; the supported provider explicitly supplies the KD symbols, so a missing-symbol mismatch must not be treated as an authorized mixed protocol.

**But not a permanent isolation guarantee:** initially missing Native lock CALLs take the ordinary original-task native suffix. The daemon may subsequently learn those targets. The checked-only context list explicitly names Native mutex/rwsem/IRQ/BH/scheduling APIs (`disassem/context_symbols.py:34–95`), but production sets that list to empty and bypasses analysis (`disassem.py:131–152`). Therefore a later generation can decode their real implementations rather than hit a dedicated Native-lock service. Native objects remain Native objects; context, native acquisition records, blocking, task identity and exception/fault semantics of remote execution are not thereby established.

Known mixed **KD mutex→KD unpinned spin** CALLs are a separate implemented path: one physical CAS/exact spin ticket, ledger registration, and pending native continuation on failure (`lock/mixed_calls.inc:8–48`; `control_calls.inc:283–301`). A pinned spin control is deliberately sent back to the waiter to consume its preexisting pin. Sleeping KD mutex calls under a spin proxy are also native continuations, not permission to sleep while holding a spinlock (`control_calls.inc:304–312`). Neither rule automatically covers unrelated Native inner locks or an inline context-changing prefix.

M transfers a sole eligible outer mutex only on the exact mixed contention route, otherwise retains owner/frame/source state through native unlock ACK (`mutex/combiner.inc:360–402`; `execution/native.inc:35–48`). C additionally has queued role exchange for that eligible transfer (`mutex/combiner.inc:298–353,552–601`, C), with old-frame/source retirement before the new queue becomes runnable and a native-custody barrier. It closes its proxy epoch before FULL/native services (`combiner.inc:533–545`, C). Neither commit performs an arbitrary lock-owner/combiner swap for every instruction or CALL exit. C's retained native lock tracking/IRQ guard is bounded and does not track arbitrary Native mutex/rwsem reads (`mutex/custody.inc:58–118`, C).

## 6. Possible finer-grained implementation — inference, not existing support

A persistent hot-prefix/native-cold-path design is feasible in principle, but is a separate correctness change, not just removal of an entry rejection. The narrowest extension is a terminal exit at an exact source instruction boundary; it need not call runtime for normal PAUSE/fence/atomic instructions and should not resume the same JIT after an arbitrary native suffix.

Required work would include:

- Define which decoded/unlowerable boundaries can emit a terminal marker, including undecodable-byte boundaries without pretending the rest was decoded. Preserve every alternate reachable branch and complete original source residency; do not suppress an error by silently omitting a block.
- Publish generation-bound source sites/bytes and validate exact RIP/SP/packet provenance at runtime. The current runtime opcode whitelist and spin root restrictions cannot simply accept an arbitrary reported RIP.
- Preserve scalar GPRs and source arithmetic flags, virtual stack/real CALL words, and every already committed memory effect. No replay after a prefix. Source FPU, vector, control-register, fault/exception-table or hardware-context effects require their own contract if any are executed before the boundary.
- Retain exact physical owners/acquisitions, task routes, source leases and final ACK/frame retirement across native execution, including nested/early-outer cases. Do not replace these with approximate counters or context equality alone.
- Define how a marker remains valid without globally banning future delegation; the current sticky native-only policy must change deliberately with source/image lifetime and repeated-escape behavior kept explicit.
- Treat unknown indirect targets, branch-budget exits and cross-function root RETs separately: their current error packet is not automatically flags-aware or a valid native CALL continuation.
- For IRQ/BH/preempt transitions, prefer explicit local boundaries initially. Merely saving/comparing flags does not transfer CPU-local exclusion, active-mm, RCU or scheduler state; an executor-state installation scheme needs independent invariants and restoration at all exits.

Costs would include marker code/metadata, FULL packet materialization, runtime validation, waiter wake/ownership or borrowing handoff, final unlock ACK, and loss of delegation for the remaining suffix. Ordinary generated branches retain branch/budget instrumentation; faithful PAUSE/fence/LOCK lowering should need no additional per-instruction runtime roundtrip. The PAUSE alias defect must first be repaired and tested. Relative cost and benefit for real API bodies are **unmeasured** here.
