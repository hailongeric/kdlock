# Selected real-API lock and critical-section map

This is a source and emitted-object audit, not a new implementation, build, test, benchmark or VM run. No repository files were edited. References marked **VERIFIED** were inspected in source or retained ELF; **OBSERVED** describes a retained test/campaign receipt; **INFERRED** describes a feasible integration consequence requiring its own validation. A conditional unsupported operation does not, by itself, disqualify the entire critical section: an executed prefix can remain useful if the reached exit has exact native continuation/ownership support. Conversely, complete source publication is not evidence that every reached return/escape works.

## OFD: exact query and all participants

**VERIFIED native source.** `posix_test_lock` gets inode/lock context before acquiring `ctx->flc_lock` (`K/fs/locks.c:1011–1026`). It walks the POSIX list; `posix_test_locks_conflict:980–993` preserves F_UNLCK same-owner lookup, ordinary conflict owner/type/range tests; `posix_same_owner:689–692` is pointer equality. On match, `locks_copy_conflock:415–430` copies owner/pid/flags/type/range and can invoke `lm_get_owner`. An expirable lock condition at `1030–1038` invokes `lm_lock_expirable`, takes a module reference, unlocks, invokes expiry, drops the module reference and retries. Neither callback occurs on a local callback-free record. The basic body reads the list and writes the caller's result structure; it does not mutate shared list topology. Native `vfs_test_lock:2263–2272` may dispatch a filesystem-specific lock method before reaching this CS.

**VERIFIED adapter.** `R/workload_modules/real_api/module.c:71–111` substitutes `posix_test_lock`; `80/110` use `RB_LOCK/RB_UNLOCK` on the actual `ctx->flc_lock`. KD macros `29–33` use spin DIRECT continuation; `186` asserts native spin size four bytes. Binding `198–217` checks every existing lock is OFD and has no `fl_lmops` or `fl_ops`; it records the native address. The adapter then inlines comparisons/copies and omits callback branches on that established frozen input. Redirection matches exact inode (`147–164`); it is not a conversion of every consumer of that inode lock. This is a narrower structural transformation than retaining the original native call graph.

**VERIFIED emitted Native object.** `build/fs/locks.o:posix_test_lock` is at `0x3d00`, size `0x213`; lock relocation at `0x3d5d`, ordinary unlock `0x3db3`, conditional indirect expiry callback `0x3e5a`, unlock/call/retry sequence `0x3e84–0x3e9e`, copy helper `0x3f0a`. No inline LOCK/fence/IRQ instruction is present in the extracted function; that does not say what external lock/callback helpers do. The ordinary result-copy CALL is source-level work to translate/learn, not a reason to reject the entire query. Missing-callee native exit, if reached, ends this JIT episode and executes the suffix on the waiter.

**INFERRED integration.** A minimal experiment should change the original lock calls and preserve both callback branches, with per-reached-path exact native exit or supported translated callee. Do not pre-refuse all OFD queries because some records can expire. Conversely, arbitrary callback code and unlock/retry lifetimes need explicit evidence. Additional participants include `locks_owner_has_blockers:341–355`, flock mutation `1133–1196`, POSIX mutation `1206–1430`, lease break/reacquire `1597–1704`, lease removal `2745–2759`, final file-lock teardown `2775–2788`, `vfs_inode_has_locks:2814–2826` and `/proc` fd lock display `show_fd_locks:2998–3013`. A single converted GETLK site may not share native qspinlock state with these unchanged users. Excluding them is valid experimental scope, not general integration. Nested blocked-lock/per-CPU global-lock work in mutation paths must be handled when those participants are included; it is not mandatory GETLK work.

## setfd: small writer with a wider object protocol

**VERIFIED native source.** `set_close_on_exec` captures `files = current->files` before locking (`K/fs/file.c:1278–1283`); protected helper `__set_close_on_exec:322–331` sets a bitmap bit or tests then clears it. `files_fdtable(files)` is evaluated while held. `get_close_on_exec:1286` uses RCU/current-filetable lookup; it is the separate verification syscall, not a second exclusive CS. Native ordinary spin locking preserves the caller's IRQ state and disables task preemption while held; the selected syscall enters task context, not hard IRQ context.

**VERIFIED adapter.** `R/workload_modules/real_api/module.c:117–127` keeps current/files lookup before lock and the exact test-before-clear. It operates on `files->file_lock`, not a private KD spin allocation. Bind/hold uses exact files_struct reference (`219–250`); redirect matches that file table (`157`). Opening, closing, duplicating and resizing are excluded while bound. Distinct per-worker descriptors do not remove cacheline sharing in the bitmap.

**VERIFIED emitted Native object.** `build/fs/file.o:set_close_on_exec` at `0x2a80`, size `0x72`: GS `const_current_task` load `0x2a86`, files load `0x2a9b`, lock CALL `0x2aab`; protected instructions include unprefixed BTS `0x2abd`, BT `0x2ae2`, conditional unprefixed BTR `0x2aec`, then unlock `0x2ac8`. These are not LOCK-prefixed atomics or mandatory fences. No protected-body CALL occurs in this exact build. The bitmap bit operations still need faithful JIT flags/memory semantics; old returned-body observations are scoped evidence, not a new unchanged-native-body run.

**INFERRED integration.** This is a favorable minimal lock-call replacement candidate for the selected CS. Required same-object participants include `dup_fd:407–464`, `alloc_fd:570–611`, `put_unused_fd:634–639`, `fd_install_slowpath:660–669`, `close_fd:734–741`, `__range_cloexec:762–773`, close-range unlock/relock `783–805`, `file_close_fd:879–886`, replacement/dup `1359–1369,1441–1456`, and `iterate_fd:1513–1531`. Table expansion deliberately unlocks for allocation and reacquires (`250–267,289–305`); exact reached native transitions can preserve that behavior. The small F_SETFD body does not need to inherit those conditional costs, but those participants cannot remain on an incompatible lock protocol.

## Pipebytes and pipecap: exclusive query paths versus conditional mutation

**VERIFIED native/source scope.** `pipe_ioctl(FIONREAD)` (`K/fs/pipe.c:619–637`) takes the pipe mutex, loads head/tail, loops over `pipe_buf(...)->len`, unlocks, then `put_user`. User fault/mm work is outside the selected CS. Empty ring skips the loop. `pipe_fcntl:1427–1451` validates the object, holds the same mutex across a command switch: GET reads `max_usage * PAGE_SIZE`; SET invokes resize. Selected GET does not allocate, perform user copy or modify pipe state.

**VERIFIED emitted object.** `build/fs/pipe.o:pipe_ioctl` at `0x1e0`: lock relocation `0x224`, unlock `0x27b`, user-copy relocation `0x285`. The FIONREAD slice between lock and unlock has no CALL, LOCK prefix or fence. `pipe_fcntl` at `0x2e70`: lock `0x2eb0`, GET branch load/shift `0x2f84–0x2f88`, unlock `0x2ed5`; SET-only instructions include `LOCK XADD` at `0x2f36/0x2fa1`, capability checks and `pipe_resize_ring` at `0x2f7c`. These conditional instructions are not mandatory GET instructions.

**VERIFIED adapter.** `R/workload_modules/real_api/mutex.c:99–141` reproduces the query arithmetic in `rb_body` and copies FIONREAD result only after RA_UNLOCK. KD's object is `static struct kd_mutex kd_lock` (`62`, initialized `318`), whereas Native uses `original_lock = &target_pipe->mutex` (`291`). Public versus historical OUTER shells are selectable (`64–82`) and remain separate evidence. `redirect:234–246` requires TGID, pipe identity and exact command; binding rejects watch queues (`284–289`). The native loop reloads `pipe_buf`'s mask expression where compiled, while adapter caches `ring_size-1`; correctness under mutex is plausible but this is still copied/specialized code, not literally unchanged native body. The pipecap adapter removes the native command switch/SET graph.

**INFERRED integration.** Preserve native function/control flow and replace lock calls plus object routing. A prepared exclusive query body can delegate; no specific mandatory current/mm blocker was found inside the selected branches. For SET, a branch-specific exit before a scheduler/IRQ-sensitive call can preserve an already executed prefix. Successful decoding of LOCK XADD must not be equated with scheduling/IRQ state compatibility deeper in resize. No claim of full SET support is made.

**VERIFIED wider participants.** Same pipe mutex is used by exported `pipe_lock/pipe_unlock:88–99`, ordered double-lock `102`, read/write `282–392,458–574`, watch queue size `642`, release `729`, fasync `754`, FIFO open `1154`, and fcntl `1436`. Splice/tee/vmsplice also use the exported wrappers. Reads/writes can copy user memory while held, invoke buffer operations, allocate, inspect current, signal SIGPIPE and drop/reacquire the mutex around empty/full waiting. Poll is intentionally lockless (`658–685`), so conversion must preserve that algorithm rather than serializing every read. The current frozen ring/descriptors/no independent consumers rule avoids these interactions; it is not all-object conversion. There is no demonstrated parking cause in these source facts.

## Seek: native acquire/return/callee/cleanup spans

**VERIFIED native source.** `K/fs/read_write.c:395–409` uses `CLASS(fd_pos, f)(fd)`. `fdget_pos` (`K/fs/file.c:1255–1264`) first obtains the reference and tests shared atomic-position requirements (`1230–1238`), then acquires `file->f_pos_lock`. It returns to ksys_lseek while still held. `vfs_llseek:387–391` checks FMODE_LSEEK then invokes an indirect filesystem method. Tmpfs `E/mm/shmem.c:3665–3682` sends SET/END to `generic_file_llseek_size` with an i_size read; DATA/HOLE alone take `inode->i_rwsem` and call `mapping_seek_hole_data`. Generic code `K/fs/read_write.c:104–140,159–186,57–73` computes END offset, checks valid range and updates f_pos only when changed. SEEK_CUR's f_lock branch is conditional, not SET/END work. Cleanup `K/include/linux/file.h:76–85` calls `__f_unlock_pos` (`K/fs/file.c:1267–1269`) then fdput, so fput is outside this lock. Linux7 has no old f_version store here. On the captured x86-64 target i_size_read is an acquire load, not the conditional 32-bit preemption path (`K/include/linux/fs.h:1127–1148`).

**VERIFIED emitted object.** `build/fs/read_write.o:ksys_lseek` at `0x9c0` has fdget_pos relocation `0x9d6`, actual indirect-thunk llseek CALL `0xa0c`, cleanup unlock `0xa21`, conditional fput `0xa61`. `E/build/mm/shmem.o:shmem_file_llseek` at `0xf10` dispatches SET/END directly to generic_file_llseek_size (`0xfc5` relocation); its `down_write`, mapping search and `up_write` belong DATA/HOLE. No source-level claim that all seek operations necessarily acquire a second lock is valid.

**VERIFIED adapter differences.** `R/workload_modules/real_api/mutex.c:143–175` replaces ksys_lseek, performs fdget/fdput outside a new paired rb_body, bypasses the original fd_pos conditional acquisition and indirect filesystem dispatch, reads i_size only for END, uses the bound sb maximum and implements the specialized range/f_pos store. Binding accepts only unlinked tmpfs and generic/shmem llseek with FMODE_ATOMIC_POS (`293–302`); redirect permits only exact fd plus SET/END (`245–246`). Thus it establishes a simpler, same-function continuation; it does not validate the original split native return path.

**INFERRED specific blocker/evidence gap.** The arithmetic path is plausible delegated work with no mandatory current/mm/user access after acquisition. But replacing mutex_lock inside fdget_pos must continue through its root RET into ksys_lseek, then indirect filesystem llseek, then cleanup unlock. Current translator RET dispatch uses a known return-target whitelist, not an automatic native escape for every unknown outer return; unknown IJ returns are errors. Therefore mark this exact graph **unvalidated**, not generally impossible and not solved by the existing rb_body run. A proved wrapper/continuation scope or explicit exact native suffix at a supported boundary is required; avoid rewriting the native operation to hide the issue. Other f_pos participants include read/write/readv/writev and directory iteration through fd_pos, plus file initialization/type union rules. Their user-memory/filesystem/accounting work cannot silently use Native while this description is KD-bound.

## UTS: retain sleeping-rwsem semantics and native notification placement

**VERIFIED native source.** Global `DECLARE_RWSEM(uts_sem)` is `K/kernel/sys.c:1308`. Newuname takes read at `1370`, obtains `utsname()` and copies at `1371`, releases `1372`, then user copy/personality fixups. `K/include/linux/utsname.h:29–31` resolves current->nsproxy->uts_ns. Host/domain writers validate capability, length and user copy and mix entropy before locking. Successful native writers unconditionally do `u=utsname(); memcpy; memset; errno=0; uts_proc_notify; up_write` (`1449–1455,1503–1509`). Notification is mandatory for every successful setter when CONFIG_PROC_SYSCTL is enabled, even if nobody is waiting; wake work inside it can be conditional. Supplemental `E/kernel/utsname_sysctl.c:130–135` calls proc_sys_poll_notify. Sysctl readers/writers also use this global semaphore (`49–65`) with their original split read/modify/write semantics. Unrelated namespaces use the same native uts_sem.

**VERIFIED emitted object.** `build/kernel/sys.o:__do_sys_newuname` reads GS current inside its read-held interval (`0x18b2`, down_read `0x18ae`, up_read `0x18f9`). Setters cache current in a preserved register before down_write in this exact build; namespace dereferences still occur after down_write. Host down_write/memcpy/notify/up_write relocations are `0x49b8/0x49d3/0x4a01/0x4a0d`; domain equivalents `0x4b88/0x4ba6/0x4bd4/0x4be0`. Supplemental uts_proc_notify object calls proc_sys_poll_notify; source-only wake helper expansion is not a measured cost or a claim every caller actually sleeps.

**VERIFIED adapter.** `R/workload_modules/real_api/uts.c:1–9,38–61` uses private Linux rwsem for Native but private KD/TC rwlock for the comparison; stock alone retains global uts_sem. Writers copy a fixed 64-byte buffer plus zero byte (`64–69`); target namespace/field is selected before RA_WRITE. Read snapshot uses bound target_uts rather than an in-CS current lookup (`71–77`). The copied syscall handles only 64-byte native-personality calls; notify is deliberately after unlock (`79–92`). No proc sysctl observers, independent users or namespace changes are permitted. These are material topology/type/body/order differences, not just lock-call replacement. All three matched arms sharing the specialization does not make it the native UTS critical section.

**INFERRED integration.** Keep actual global semaphore and use a corresponding KD rwsem family with local readers; do not classify native rwsem→rwlock substitution as preservation. Writer copy/zero prefix may delegate, then a reached missing/native notification CALL may transfer the original suffix (including up_write) to the waiter without replay. That preserves native ordering if the exact rwsem phase/owner/ACK and call-return graph are supported. A merely conditional helper branch cannot justify denying the whole write; here the notification CALL itself is mandatory and may make every successful writer a partial-JIT episode if not translated/supported. The prefix may still be useful, but no gain is established. Current GS lowering can address the logical origin; that alone does not virtualize active hardware mm, scheduler state or IRQ context. Readers stay local regardless. Global conversion must include new/old uname/gethostname, both setters, proc sysctl reads/writes and namespace-copy readers; redirecting one TGID/private namespace is not that conversion.

## Xattr: current read policy and unmeasured writer opportunities

**VERIFIED native source.** `K/fs/xattr.c:1282–1302` takes `simple_xattrs.lock` read ownership for rb_find/strcmp, then optional size/error/value-copy work. Comparator uses `strcmp(xattr->name, key)`; absent returns ENODATA, insufficient buffer ERANGE, NULL buffer size only. No user buffer is accessed here: syscall/VFS/security/allocation/copy-to-user layers surround this kernel-buffer operation. `simple_xattr_set:1331–1405` allocates/copies new object before write_lock, then searches and conditionally replaces/erases/inserts/rebalances while held; cleanup is after unlock. `simple_xattr_list:1442–1485` is another shared reader. `simple_xattr_add:1513–1518` writes during inode initialization; init/free require correct lifetime.

**VERIFIED adapter.** `R/workload_modules/real_api/xattr.c:34–82` uses correctly typed private rwlocks for all matched arms and preserves actual rb_find, comparator order, value memcpy and errors. KD calls kd_read_lock/unlock only, never writer delegation. Preparation `117–126` does not upload an image; hook `134` checks both exact target_xattrs and TGID. Binding pins an immutable unlinked tmpfs inode and uses its real rb_root while substituting only the lock. Get/set/list/native operations on the same tree cannot concurrently use independent Native/private lock protocols; frozen attributes/read-only controlled participants are essential.

**VERIFIED emitted object.** `build/fs/xattr.o:simple_xattr_get` at `0x3290`: read-lock `0x32b6`, strcmp `0x32ca` on each visited nonempty node, read-unlock `0x32e7`, conditional memcpy `0x3324`. Those conditional CALLs do not turn this read-held operation into an eligible writer. KD's no-read-delegation policy is the decisive rule, not a claimed backend inability to translate strcmp or memcpy.

**INFERRED expansion.** Native set/add write CS could be evaluated separately with exact rb-tree and caller lifetime. Allocation failure before write_lock is not a mandatory allocator call inside every writer. Conditional replace/erase/rebalance callees can be translated or use exact native suffix transitions if supported. This row supplies no executed evidence for those writer branches. Front/tail labels select keys, not rb-tree depth; do not transfer Linux6.1 linked-list/JIT conclusions.

## Instruction granularity and why CALL-level exit differs from per-instruction exit

**VERIFIED shared translator contract (both requested revisions).** Reached missing direct CALL can terminate a JIT episode and run original callee plus suffix on the waiter (`disassem/context_policy.py:50–103`, `special_inst.py:109–115`, `indirect_jump.py:119–134`; `kernel_module/exe.c:617–640`). CALL return words must remain real, source leases and logical/physical owners live until the real unlock ACK. Future learning can produce a different image; this is not arbitrary return-to-JIT after an unknown native callee. Decoded ordinary callees, known lock controls and supported scalar hostcalls have distinct resumable service paths. Unknown RET targets use indirect-jump failure (`special_inst.py:122–125`, `indirect_jump.py:18–90`, `kernel_module/exe.c:669–674`), hence the seek caveat.

**VERIFIED native-inner-lock limit.** `kernel_module/execution/registry_lifecycle.inc:91–118` binds recognized spin/mutex controls to KD entry points (`kd_spin_lock_legacy`, `kd_mutex_local_lock` and direct wrappers), not arbitrary Linux Native mutex/rwsem entries. `disassem.py:158–196` mirrors that registry. A first-generation missing Native inner-lock CALL may exit to the original waiter, but trusted-source learning can subsequently translate that callee; the checked analyzer’s Native-lock/context bans are not a permanent production service boundary. Consequently an initially successful CALL-miss suffix is not proof that every later learned mixed Native/KD lock chain preserves task/IRQ/owner semantics. Any proposed wider pipe/UTS/seek integration must record and validate the reached graph and exact context, or provide an explicit supported routing boundary; this is a concrete runtime gap, not a reason to deny an unaffected query prefix.

**INFERRED cost/semantic distinction.** CALL-level native exit can avoid having to interpret the helper's task/mm/IRQ-sensitive implementation and preserve a useful prefix, but may move all remaining work to the origin and incur capture/transfer/ACK overhead. Fine-grained supported instruction exit could reach a later point inside a helper, but only with an exact instruction descriptor, operand/flags/control-flow and runtime continuation. It cannot be assumed for arbitrary unsupported opcodes or user-memory exception semantics. No selected API is rejected here merely because an untaken branch includes an unsupported service. Likewise no frequency/latency claim follows from a source CALL or fence label.

**Decoder finding supplied by the parallel audit:** the captured Miasm registration for PAUSE is commented out, so source `F3 90` decodes as prefixed NOP and `disassem/special_inst.py:105` emits bare NOP, losing the REP/PAUSE hint. This is a concrete faithful-lowering gap for any reached PAUSE, not a reason to claim every selected API body contains one. The protected setfd, FIONREAD and GETPIPE_SZ slices inspected above contain no PAUSE. Conditional Native inner-lock/wait-loop learning can expose PAUSE and needs that separate decoder correction and context proof; merely leaving a CALL unresolved in the first image does not establish enduring safety. This audit did not execute the decoder; the parent’s separate exact-byte decoder receipt is the authority for that finding.

Native object excerpts are saved at `/tmp/kdlock-real-api-disassembly-20261030/` with object hashes and exact offsets in `summary.json`. They are static `.o` observations, not decoded KD images or evidence of the path taken in a timed run. External helper bodies, runtime alternatives/ftrace state and lock replacement recompilation can change emitted instructions. In particular source memory-order helpers need not emit MFENCE/LFENCE on x86; the actual selected simple query slices inspected here contain no mandatory such hardware fence. Parent's separate translator/spin-context audit covers the exact supported opcode table and saved-context contract.

## Concrete documentation corrections / next evidence, no implementation implied

1. `R/docs/BENCHMARK_WORKLOADS.md:173–175` says adapters do not reinterpret existing Linux locks. That blanket statement conflicts with OFD/setfd source using actual native spin storage under four-byte/frozen-participant constraints; `R/bench/real_api/README.md:221–225` states the more precise split. Describe each adapter's binding individually.
2. UTS should remain labeled a private rwlock specialization and notification reorder. A future minimal native UTS integration must retain global rwsem participants and in-lock notification; prefix/native-exit feasibility should be evaluated rather than moving the operation.
3. Seek's copied locally paired body does not establish cross-function native root-return/cleanup support. Obtain exact continuation/return graph and reached-exit evidence for that specific integration.
