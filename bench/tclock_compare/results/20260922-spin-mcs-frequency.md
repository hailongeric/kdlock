# 2026-09-22：spin CPU 热度改为 MCS 入队频率

本实验已因性能退化按用户要求撤回，当前代码恢复 `bf16b10` 的调用计数；
回退后的验证见[回退记录](20260922-spin-mcs-rollback.md)。以下保留实验时的功能与性能证据。

实验版本通过功能验证；性能存在退化。observe 下 20 线程 c1/c16 的 KD 最大吞吐
为 4.042/3.959 Mops/s，相对冻结恢复版下降 18.7%/17.3%；四线程下降 6.1%/10.8%。
实验期间采用所要求的 MCS 计数语义，没有据此调整阈值、移动准入或切换热表。

## 实现与版本

基于 `bf16b10ad6526acba0244f067e540c12bc5a0052` 的未提交改动。与冻结恢复版
逐项核对执行源码，生产部分仅变更 `include/kd_hotlock.h`、`kernel_module/kd_hotlock.c`
和 `kernel_module/spin/queue.inc`；另调整测试、生命周期探针和说明文档。
没有修改 TCLock、公共锁 API、JIT ABI 或 guest 内核。

共用 `xchg_tail()` 在交换队尾前记录一个 CPU 事件，覆盖原生、代理、虚拟嵌套，
统计归属实际执行发布的 CPU。fast/pending、发布前取消、节点耗尽 CAS 轮询、
队首接棒和正文不计数，回退由最终发布点计一次。新接口不接收锁地址、不查询
哈希表、不改变抢占计数，复用本地 busy 保护；`spin_delegate=0` 仍跳过统计。

入口继续读缓存 CPU 热值，CPU 热时按完整地址增加单锁调用计数。CPU 每 1024 次
MCS 入队检查 400 亿 TSC ticks，单锁每 1025 次调用独立检查 25 亿 ticks；
mutex 保持原有调用计数及同次采时复用。256 桶／256 记录与对象布局保留。
CPU 晋升只影响下一次入口，不重新准入已入队请求。只走 fast/pending 时 CPU
缓存热值可以持续保留；降温仅在下一批 MCS 到期确认。上述语义仅属于已撤回实验；
当前[执行路径](../../spin_cacheline/EXECUTION_PATHS.md#51-准备热度与快速获取)已恢复调用计数。

## 功能验证

全部构建和运行在 recovery guest，内核 `6.1.159-kdclobber2`，Build ID
`5ca28058e156f34a2c7fe91e8e0fbf92f4e51960`，voluntary、nokaslr；核验捕获基线及
恢复快照后才加载模块。normal/SELFTEST 均完成 W=1 构建。保留原有 objtool
栈切换/RETHUNK 警告；初次构建还有 Perl locale 警告，无新增警告类别或编译错误。
热表 entry/table/cpu 的 ELF 大小仍为 24/6688/13376 字节，node/continuation
为 128/704 字节。

- 基础及定向单元 6/6，通过 13 个热度错误变体检测；运行器单元通过。
  覆盖 CPU1024／锁1025、独立采时、缓存降温、倒退/零时间、查询、CPU/type 隔离、
  重入/抢占配对、同桶完整地址及满容量。新增回退计数断言后单独重跑 shadow
  组件，NUMA 关/开均通过；取消、回退、节点复用、接棒和正文计数均检查。
- 原生协议 pthread 组件完成 400000 次互斥操作。确定性组件运行生产路径，但
  CPU、时间与 peer 动作是替身；不把这些结果当成真实内核竞争。
- SELFTEST 热表准备显式模拟 MCS 事件，日志标记 `preparation=simulated_mcs`。
  满表 `retained=1 full=1`，解锁 `word=0`，mutex 等待 CPU 1→2、`balanced=1 ret=0`，
  owner/ACK 探针零失败，正常退休卸载。这一组件会话 `mutex_jit=0`。

真实功能会话使用 normal provider，各 c1/t4、每线程 100000 次。单 CPU 48000 次
普通预热后 JIT 计数均为零；adaptive 通过原生竞争自然累积 MCS 热度，没有模拟
事件或强制热值。以下三场业务、IRQ/preempt、ACK/队列、来源退休和排空均通过，
无新增内核错误：

| 模式／场景 | 完成操作 | 实际 JIT 正文 |
| --- | ---: | ---: |
| adaptive/plain | 400000 | 224077 |
| observe/nested | 400000 | 385449 |
| observe/early | 400000 | 99921 |

这些实际 JIT 会话装载默认 `mutex_jit=1`，只执行 spin JIT，不代表 mutex JIT 已验证。
未跑全量单元、更广的资源/取消 live 矩阵或 PMU 归因。

## 性能口径

Linux 原生、TCLock、当前 KD，plain；observe 与 adaptive 使用独立目录。
每模式 c1/c16 × 1/4/20 线程 × 三后端 × 两轮 = 36 场，共 72 场。
每线程 100000 次，奇数轮后端逆序；单 CPU 48000 次预热与 JIT 准备不计时。
各后端取最大有效吞吐，ns/op 使用同一获选会话，全部两轮样本保留。
吞吐统计完整获取、正文、释放、锁外工作及循环，不是独立获取锁的延迟。

40 个 vCPU 按编号固定到宿主 CPU0..39，运行前后映射一致；本次使用的前 20 个
CPU 对应宿主 NUMA0、socket0。两模式均 36/36 有效、各完成 30000000 次计时内操作；
16/16 场竞争 KD 有实际 JIT。8 场单线程 KD 为 NO_JIT，最终没有热表记录，
与普通无竞争调用不加热 CPU 的语义一致。TCLock 代理次数仍为 UNMEASURED。
全部业务、IRQ/preempt、内核日志和排空检查通过，结束无 worker/daemon/provider 残留。
