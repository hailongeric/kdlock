# 2026-09-20：本地热锁哈希与稳定角色

本阶段基于单锁字提交 `aa389e6`，此前基线为 `7e2460c`、无行为变化清理为
`f17bb3a`。spin/mutex 各自使用每 CPU 16 桶、6 候选的索引链表，完整地址匹配；
满表替换先摘旧链，error 防止继承虚假热度。默认 adaptive 使用
`score-error >= 10000`，observe 固定准入。批量时钟和窗口参数未调低。
原全局晋升集合已删除，owner/ticket/frame 独立于统计淘汰，解锁不查询热表。
mutex 只改发现和准入，仍使用原互斥协议；没有安装整个内核的 spin 替换。

## 验证与修复

全部构建、测试和测量在 kdclobber2 recovery guest，内核未改，Python 使用既定
venv；快照 `pre_static_boot_20260915` 已由 monitor 确認。正常及 SELFTEST
provider 构建通过，保留已有 objtool 汇编告警。仅运行基础及直接相关检查：

- 生产哈希代码的碰撞、重复地址、桶首/中/尾摘链、替换误差、独立精确计数
  oracle、窗口边界/降温、CPU/类型隔离、重入丢样、observe/query 与分配失败。
  四项 mutation 检查捕获错误阈值、继承分数及窗口边界错误。
- 单锁字的直接释放、ticket/借用 ACK、队列、嵌套、早释放/重新获取、受检续跑、
  frame 退休，以及 mutex 资源回归。增加角色时原先扩大了 frame 布局，被现有
  outer fixture 捕获；改用原 state 槽位内空间后通过，寄存器偏移仍为 72，
  context 大小仍为 5400，未放宽布局断言。
- 真实 SELFTEST 持有 KD 锁时自然淘汰该候选，owner 不变，解锁后 word=0。
  真实原 mutex 等待线程从 CPU 1 迁移到 CPU 2，preempt 平衡；独立 entry
  SELFTEST 两次 ACK、保留 pin/借用及最终卸载通过。该组明确是 JIT=0。
- 显式双锁 `nested` 与 `early` 分别取得 383017/47503 次真实 JIT 正文及数据/排空证据；early
  同时观察到外锁乱序释放。初次 nested 已有正文，但运行器把新登记的 B 续点
  误当成唯一根入口而报错。运行器改为核验精确根 PC，并限定其他条目的范围、
  lock kind、pid 和状态后，两项独立重跑通过；保留初次失败记录。
- 初次 adaptive smoke 的 c16/t4 数据正确但 JIT=0，按 NO_JIT 保留；相同配置
  诊断重跑有实际 JIT，CPU 候选 lower 均超过阈值。没有据此宣称修复了调度
  随机性。运行器现在区分有效性能样本和实际 JIT 验收；observe 竞争正例仍
  必须有真实正文，adaptive 的 NO_JIT 不会记作 JIT PASS。

## 固定与自适应策略

沿用 1/16 cacheline × 1/4/8/16/20 线程 × 五轮，每线程 100000 次，单 CPU
48000 次预热、相同 CPU 放置和锁外计算。observe 包含 Linux/TCLock/KD 三臂；
adaptive 只改变 KD 装载策略，其他参数相同，各冷 CPU 的升温前缀保留在计时内。
两策略顺序运行，未交替随机配对。单线程 NO_JIT 合理，不算代理正例。

observe 150/150 场、147000000 次操作正确排空，40/40 竞争 KD 场次有实际 JIT，
共 45987385 次 JIT 正文。adaptive 50/50 场、49000000 次操作正确排空，
36/40 竞争场次有实际 JIT，共 8078272 次正文。

四个竞争 NO_JIT 场次为 c1/t4/r3 和 c16/t4/r0–2，均正确排空；不能计入 JIT PASS。
