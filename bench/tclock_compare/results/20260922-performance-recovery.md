# 2026-09-22：热表性能回归定位与局部回退

高竞争退化已通过局部回退恢复。保留当前锁协议、fast 路径拆分、普通 spin IRQ/BH
语义、704 B continuation、最终退休及 wrapper 栈修复；仅恢复此前性能最佳的
热度采样实现。所有已有工作和诊断候选均保存，没有重置整个仓库或提交 Git。

## 发现与因果边界

历史 fast-path 批次到 direct-mapped 批次，20线程 c1 约5.039→4.008、c16
约4.813→3.865 Mops/s，同期 Linux/TCLock基本稳定。归档源码及ELF核对显示，
这两个批次间执行代码差异仅为 `kd_hotlock.c/.h` 和 spin 的采样入口调用；
退化早于普通 spin IRQ 修改，不能归咎于该修改。

本轮重启后还发现环境偏差：guest CPU0..19 虽属同一虚拟 NUMA 节点，QEMU
线程可在宿主CPU0..39跨插槽调度，实测其中10个落在另一插槽。未固定时20线程
c1 的 TCLock/KD为2.616/2.372 Mops/s。保留该36场批次后，在无在途请求时
把40个vCPU按编号一对一绑定宿主CPU0..39；guest前20CPU对应物理插槽0。
固定后同一版本 TCLock/KD恢复至5.023/4.027，KD自身的约20%退化仍存在。
原亲和性与实际落点均保存；绑定仅对当前QEMU进程有效，重启须重新核对。

随后保持当前协议/IRQ修复，在独立guest源码目录只替换采样器。每个配置两轮，
取有效最大值，未增加旧版KD作为正式成绩臂；以下候选仅用于本轮授权的回退定位。

| 隔离输入 | c1 / 20线程 Mops/s | c16 / 20线程 Mops/s |
| --- | ---: | ---: |
| 回退前：直接映射、无busy | 4.027 | 3.979 |
| 之前最佳采样器，仅加现有API兼容入口 | 5.144 | 4.777 |
| 删除busy/核心pin检查，尚未共享表 | 4.110 | 未测 |
| 再共享表，尚未直接映射 | 4.120 | 未测 |
| 无busy版本仅恢复旧表字段偏移 | 4.032 | 未测 |
| 最佳实现仅删busy获取/释放 | 4.109 | 未测 |
| 当前直接映射仅加回busy | 4.073 | 3.969 |

可以确定：恢复旧采样实现能恢复高竞争性能，退化在删除busy那一步已出现，
并非新增1024槽数组或共享表才引入。**不能确定：busy判断本身就是微架构根因。**
只加回busy不恢复、只恢复字段偏移也无效；指令布局/执行时序等相互作用尚未
证实。没有把减少操作数等同于加速，也没有为解释成绩虚构缓存miss或内存序结论。
由于未获得更小且可靠的修复，按用户授权回退到已验证最佳实现。

当前版独立PMU诊断为c1/20线程，TCLock/KD各两轮stat和两轮sample，共8场、
3.2亿次操作；每场每线程200万次。KD约2601–2609 instructions/op、12838–13013
cycles/op，TCLock约830–838 instructions/op、10225–10422 cycles/op。
这些是全部20个worker累计计数，包含等待。周期采样约87%/89%分别在KD/TCLock
排队等待函数，KD热表函数本身约0.23%；不能把全部差距归为热表指令执行时间。
计数运行比例至少99%，采样无丢样，全部业务/恢复/排空正常。PMU长批次不混入
正式短批次成绩，也没有采集足以证明cache-to-cache或代码布局因果的事件。

## 最终实现与功能验证

恢复 `kd_hotlock_access()` 的四个固定入口编译时展开、本地busy、复用已有pin
的检查，以及每CPU独立spin/mutex类型表。每类型256桶/256条记录，完整地址
处理碰撞，表满保留旧身份；没有候选排名。CPU1024/单锁1025的时钟批次不变。
`kd_hotlock_record_spin_pinned()` 保留为共享采样器的兼容入口：读取已有抢占
计数，但在spin已有acquisition pin时不增加disable/enable。

这撤回了无busy核心、共享表和1024槽直接替换三项实验。entry/table/cpu为
24/6688/13376 B，CPU对象64B对齐，由模块初始化一次alloc_percpu；恢复对应
碰撞/满容量/重入检测，不通过删测试或跳过采样来获取吞吐。20个CPU的最终计数
与回退前吻合（本次c1样本CPU0 count=402，其余count=577，均hot）。

只在现有recovery guest `6.1.159-kdclobber2` 构建/执行；Build ID
`5ca28058e156f34a2c7fe91e8e0fbf92f4e51960`，voluntary/nokaslr，未改TCLock或内核。

- 基础2项，加hotlock sampling、spin preempt/direct/entry，共6/6单元通过；
  11个采样错误变体全部检出，19条获取路由仍只保留一次acquisition pin。
- adaptive/plain，4线程各100000次，完成400000、实际JIT正文242180，排空通过。
- 普通/SELFTEST模块构建与布局通过；continuation仍704 B、存储栈8512 B、节点128 B。
- SELFTEST验证真实持锁时填满热表仍保留身份/owner，解锁后word=0；mutex
  从CPU1迁移到CPU2且抢占配对正常，spin entry自测通过。此探针mutex_jit=0。
- 最终60场矩阵、adaptive和探针无内核错误，worker/daemon/provider均排空。

本轮未重跑全量单元、nested/early、mutex实际JIT、强制native续跑或IRQ/NMI
竞争矩阵；前轮对应IRQ功能证据单独保留，不当作本次重跑。
