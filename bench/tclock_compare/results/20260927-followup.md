## 第二阶段：队列、预取与发布边界

以`7d3f603`为起点，保持NUMA选择和512正文/扫描上限，精简四处重复工作：

| 位置 | 改动 | 成本与边界 |
| --- | --- | --- |
| `spin/prefetch.inc` | 默认mode2 MINIMAL保留BP/IP，删除SP hint | 物理MINIMAL始终inline且IP/SP共行；虚拟借用始终FULL。没有运行时line检查，FULL和mode1不变 |
| `spin/queue.inc` | 非代理节点只判断socket标记 | KD生产者不再写旧RSP sentinel，删除重复字段读取/比较；真实rsp和TCLock自己的sentinel保留 |
| `spin/combiner.inc` | 两次诊断更新复用本地base指针 | 保留GS相对增量，避免两次读取同一全局指针；不引入per-CPU地址转换 |
| `exe.c` | 删除通用dispatcher尾部`mb()` | 去掉一个MFENCE；简单c1完成旁路此函数，不把它当成c1收益来源 |

公共完成、packet/native和ACK的同步没有放松。尾部MFENCE不提供独立发布契约：

| 共享状态 | 保留的发布/消费位置 |
| --- | --- |
| spin寄存器包、完成和native续跑 | `spin/queue.inc`的completed release、`spin/execute.inc`的locked release；waiter acquire |
| 远端请求、退休及ACK | `execution/remote.inc`和`execution/native.inc`在pop/状态写入后的release；对应等待acquire |
| mutex寄存器包和native续跑 | `mutex/combiner.inc`先导出包，`mutex/queue.inc`完成release或native locked release |
| JIT miss目标元数据 | 先写tgt_addr/jump_from，再由registry状态CAS发布 |
| 提前outer释放 | control handler自身发布，发生在dispatcher尾部之前，不能依靠后来的MFENCE |

拒绝交接分支的`smp_mb()`和全部owner/ACK/source生命周期操作保留。
x86上的compiler barrier和普通acquire/release通常不生成硬件fence，不能以删除它们的源码行数推算性能。
源代码模块存活lease已经按batch摊销；native路由的全局raw lock只在相关路径保护frame查找/存活，
不在本次直接去掉。后续可先用CPU本地native-root跳过无关查询，再单独评估冷路径表设计。

基础2组及batch、shadow、nondelegated、deferred protocol、entry scope、spin/mutex outer progress、
remote outer、native-after-outer共11组通过，未跑全量。
prefetch fixture验证减少一次hint但缓存行集合不变，FULL仍检查原地址集合；
PROT_NONE页面继续证明consumer不读取目标frame/packet以寻找预取地址。
deferred fixture同步到现有scan_left参数，保留真实queue/IRQ边界及预算断言，未删除测试以规避适配。
这些fixture检查协议/数据，不单独证明内核并发、hardware ordering或cache miss改善。

### 剩余成本与后续优先级

1. 跨node重点看队列头、通知行和请求包的所有权迁移；producer hint消除依赖读取，
   但prefetch本身仍有指令和带宽成本。前一正文之前预取下一请求仍保留，不重试已撤回的更远距离方案。
2. ticket的OWNED→RELEASED独占转换可单独尝试release-store；WAITING、借用计数与代际竞争CAS仍需要。
   不为省少量LOCK而在每个WAITING退休上加额外分支，必须检查整个释放路径。
3. producer prefetch helper仍有call及保存现场，可单独测试强制内联；consumer/batch小helper实际已内联。
   显式noipa/noinline栈切换边界不是普通调用开销，不机械改写。
4. FULL包按起址每64字节的三次hint可能漏掉尾部partial line；inline布局主要漏SS，其他借用对齐可能含SP。
   当前仅记录待测覆盖点，不增加通用分支或所有请求的额外hint。
5. 无效注入开关的共享CAS、无native时的全局路由查询、嵌套virtual完成的旧stack扫描，
   都可独立精简；它们主要影响复杂出口，不能用普通c1成绩推断收益。

本轮没有硬件cache-to-cache或cache miss测量。全局只读指针通常已有本地缓存副本，
一次load减少不等于一次远端DRAM访问减少；同样，删除重复prefetch只减少hint，不能声称覆盖更少缓存行。

### 实际生成代码

冻结provider ELF确认dispatcher MFENCE从1变0，spin combiner的静态prefetch位置26→25、
旧sentinel常量6→0；这些是静态位置数量，不是每次请求的执行次数。
相邻两个GS计数仍各更新一次，base指针加载2→1，该区间没有新增spill/reload；
combiner从2843缩至2734字节，栈分配仍0xf0，静态栈操作位置仍101。

七个cold helper的字节和重定位内容不变，三个后端c1 caller的地址/字节/重定位也不变。
但四个unlock helper整体前移0x70：clobber入口11320→112b0，三字节release MOV从1132f→112bf。
若text基址按64字节对齐，MOV起始偏移由47变63，跨越一条cacheline。
这是待单独试验的真实代码布局变化，不能据此断定本轮小幅吞吐变化的原因，
也不能宣称低竞争代码位置完全相同。优先评估固定hot unlock布局，而不是添加更多运行时检查。

旧provider SHA256：`a24af9333199594a435b1037084e4fe6c780217f723d554050c030a3872639f7`；
本轮：`5a745b15a8d9a047220c4c5896aeb4bb8f533e17e2f6689e254feeed432c28d4`。
完整ELF指令、重定位、窗口和方法保留在本地`elf-audit/`，只离线读取，未执行归档代码。

### 三方复测结论

当前135场全部通过业务/context/JIT/排空检查，独立归档和峰值重算审计通过。
45场KD中24场实际JIT，共292622786个计时JIT正文；全部1836个预热worker各完成48000次。
111个生产文件与冻结源码一致；保留所有快慢样本。参数与第一阶段相同，覆盖全部15线程点。

KD在8–36线程各点比同批TCLock最好值高1.24%–10.04%。相对起点KD，
这些点最好值变化−0.58%至+0.16%，不是整体吞吐提升；12/16/32/36的三轮峰值范围不重叠，
不能简单宣布全是波动或保证无回退。4线程max低1.93%，但median高0.43%；7线程max低2.68%，
median低0.20%。三轮非配对数据不足以把这些变化归因于某一处改动。
本轮保留的是冗余操作/代码精简，性能仍需以全操作数据判断。

目标尚未全部达到：1线程比Linux低5.18%，7线程比TCLock低3.83%，Linux28/36的高峰超过KD。
Linux36的高轮peak13.471/12.831、whole12.526/12.195 Mops/s，每轮全部139个可选窗口都超过10，
精确操作数25069312/24401152与payload一致，36个worker都进步、绑定CPU正确，
峰值量化上界仅0.221%/0.239%。这支持记录中存在持续高吞吐阶段，不是单个300ms窗口误差；
底层调度/一致性原因未在本轮确定。Linux28的高轮只有6/140窗口超过10，peak11.708而whole4.842，
峰值选择放大了短阶段，所有数据仍保留。

24线程的四个node1 worker只占KD整段1.10%–1.25%、峰值约0.98%，相等每worker进度的参照为16.67%。
TCLock更偏斜：整段约0.40%。全部worker为正不证明无饥饿或最大等待时间；
NUMA后续不能只看总吞吐。worker归属份额不是代理实际执行CPU的份额。
