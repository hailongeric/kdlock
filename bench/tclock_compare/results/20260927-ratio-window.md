# 2026-09-27 近似比例窗口调优

在`b79e188`的per-CPU清零计数方案上，将CPU比较间隔选为1024，默认比较
`(spin_entries >> 10) < 2`，比较后清零入口/MCS计数并采一次时钟。
比例边界仍约为超过50%，CPU采样频次减半；单锁热度保持独立的512次/12.5亿TSC窗口。
MCS间隔和入口右移位数改为两个编译期常量，没有新增运行期计数器、快照或全局热路径读取。
原生队头资格仍检查六个后继，边界随CPU间隔改为低10位；mutex采样规则不变。

当前已完成144场定向比较和最终构建/相关检查。完整15线程点三方矩阵仍待运行，
本页不将定向数据记为完整性能验收。

## 口径与范围

所有阶段使用1 cacheline、NUMA-on、固定2.5GHz、每配置三轮；每轮全worker先预热48,000次，
连续测量2秒，在排除前300ms后选择最高的完整worker cohort、至少300ms窗口。
保留全部快照、整段吞吐、三轮分布、实际JIT和排空证据；没有改为500ms或删除低样本。
worker固定到CPU0起的连续CPU，collector固定38；宿主40个vCPU一一映射及频率政策已核对。
KD批上限512、prefetch=2，TCLock保留其1024配置；当前默认`kdclobber2`内核没有修改或重建。

只有reset512阶段包含同期三方比较，后四组用于候选诊断；没有把不同阶段的后端值拼成同轮结果。
五组全部通过业务、IRQ/preempt批次、队列/frame退休及卸载检查，独立离线审计重新计算了所有获选峰值，
并核对源码/ELF哈希、全worker预热、完整计数和结果分组。合法原生完成与实际JIT分开保留。

## 候选选择与代码布局

下表为三轮最大峰值，单位Mops/s。全部三轮分布保留在匹配归档的`summary.json`和`records.json`。

| 阶段 | 8线程 | 20线程 | 36线程 |
| --- | ---: | ---: | ---: |
| reset512 | 5.7160 | 6.5681 | 6.1311 |
| tight512 | 5.7337 | 6.4545 | 6.0306 |
| short256 | 5.7273 | 6.4131 | 5.9852 |
| control512 | 5.7408 | 6.4425 | 6.0312 |
| long1024 | 5.7261 | 6.5715 | 6.1491 |

reset512在8/20/36线程相对前次历史峰值变化约-0.45%/-0.18%/-0.17%，没有出现普遍回退。
tight512接受至639次入口，约对应超过80%竞争；short256保持约50%比例却加倍CPU比较频率。
两者20/36线程下降，但不能直接将共同下降归因于比例或采样频率。

为允许cutoff5，候选曾移除仅装载时使用的二次幂参数校验。这将`kd_hotlock_init`从439字节缩到403字节，
使后续native/combiner/unlock代码整体移动32字节；short256的低位检查又使后续部分函数移动16字节。
原生主体、combiner指令和per-CPU布局基本不变，但代码位置发生了变化。
control512使用同一可执行构建、装载cutoff8，恢复`entries < 1024`边界后20/36线程仍低，
说明cutoff变化不足以解释该差异。两份模块仅非装载BTF元数据不同，代码、数据及relocation一致。
因此比较中存在代码布局差异这一混杂因素，尚未单独证明哪条缓存线或分支造成了吞吐变化。

long1024保留原有装载校验，恢复与reset512相同的函数起始地址。编译器同时将共用CPU窗口函数
专门化为固定1024，两个调用点各省掉6字节的参数准备。选择它是为了减少采样并保持已测吞吐，
不把小于1%的峰值差异宣称为普遍性能收益。
