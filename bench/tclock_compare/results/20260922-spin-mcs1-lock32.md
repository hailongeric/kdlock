# 2026-09-22：CPU MCS1 / hotlock32 与移除 busy 的合并性能

用户确认将两组改动一起测试：spin CPU 的 MCS 检查阈值32→1，spin/mutex 单锁
阈值1024→32，以及删除热表 busy/barrier、非 task 上下文跳过统计。
基于 `35414c2`，生产修改仅涉及 `kernel_module/kd_hotlock.c` 和 `include/kd_hotlock.h`。
本报告与对应实现、测试一起提交；冻结差异及基础提交保存在归档 `preflight/`。

本轮20线程 KD c1/c16 为 **5.011/4.802 Mops/s**，相比
[上一轮 MCS32](20260922-spin-mcs32.md)提高 **27.3%/23.7%**；相对
[下降前单轮基线](20260922-single-round-baseline.md)为 **+0.8%/+0.9%**，
本轮恢复到此前水平。单线程相对上一轮提高12.6%/3.3%，四线程提高3.9%/7.1%。
每配置只有一轮，且两组改动合并测量，不能分别归因于阈值或 busy 删除，也不能据此确认稳定收益。

## 当前语义

- spin CPU 仍只在共用 `xchg_tail()` 的实际 MCS 发布点计数，每次事件读TSC检查
  原400亿ticks窗口；fast/pending、发布前取消和节点耗尽轮询不计数。非 task 事件丢弃。
- spin/mutex 单锁仍累计入口调用，保留严格 `count > 32`，第33次检查原25亿ticks窗口。
  mutex CPU仍每1024次入口检查，CPU/单锁同次到期复用TSC；spin单锁独立采时。
- 入口使用缓存CPU热值，MCS更新仅影响后续入口；冷却/重新变热的重置规则不变。
  非 task 的 record/query 不访问热表，adaptive/query 返回冷，observe record固定允许；
  原有上下文及JIT安全检查继续独立执行。task调用保留抢占pin，防止同CPU task交错写表。
- 删除热表busy字段、原子占用检查和对应编译器屏障。entry/table/cpu为24/6680/13376字节，
  每CPU对象含64字节对齐填充；256桶/256精确记录、满表策略、owner/ACK/退休协议不变。
