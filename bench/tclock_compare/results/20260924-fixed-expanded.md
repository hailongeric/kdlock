# 2026-09-24：固定2.5GHz的十种线程数单轮比较

按用户最新要求，固定宿主2.5GHz重新运行1/2/3/4/5/6/7/8/16/20线程比较。80/80场通过业务、IRQ/preempt、内核错误及排空检查，共57600000次计时操作。本轮3–6线程的KD adaptive在两个正文长度下均落后于Linux Native和TCLock；16条cacheline从7线程起超过TCLock。**单轮结果不能证明稳定性或全部线程无回退。**

## 方法与范围

输入提交`77dd417`，阶段`compare-fixed-expanded-20260924`；锁代码和运行器未修改。c1/c16 × 十种线程数 × Linux Native/TCLock/KD observe/KD adaptive，每项一次、每worker100000次测量。显式`--repeats 1`，不修改默认三轮设置。各配置依次运行Linux、TCLock、observe、adaptive，未随机交错、删除或替换样本。

宿主worker CPU0..19在运行前后均核对min=max=2500000kHz，保留`intel_pstate`、`powersave`、`balance_performance`。本轮结束后继续保留固定2.5GHz限制，不恢复动态频率。上下限配置不等于连续采集了实际执行频率；本轮未采集PMU或计时区间频率轨迹。[此前动态频率矩阵](20260924-dynamic-expanded.md)单独保留，不混合统计。

全部worker参与每人48000次计时外预热，共576名预热worker、27648000次预热操作。预热与测量分别创建相同CPU绑定的worker，没有额外2秒等待；实际间隔为5.57–84.19ms。worker绑定CPU0至CPU(`threads-1`)，runner允许CPU0..19，宿主40个vCPU绑定和恢复快照均已重新核对。

guest内核`6.1.159-kdclobber2`，nokaslr、voluntary，Build ID `5ca28058e156f34a2c7fe91e8e0fbf92f4e51960`。KD策略为`mcs_entry_ratio512_simple`、`spin_contention_pct=100`、delegation on；实际加载provider的`mutex_jit=1`，此次仅spin性能负载。未重复独立单元、nested/early或全量功能测试。
