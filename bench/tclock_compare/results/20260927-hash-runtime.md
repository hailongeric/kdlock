# 2026-09-27 hash_payload：合并编译与逐请求内联

基于`74452da`继续优化。Linux/TCLock及三方hash正文不变；生产默认仍为NUMA-on、
512正文/扫描上限、kernel UBSAN和比例2。显式off/1024的诊断结果单独报告，不混合取优。
默认配置16/36线程较上一版同配置峰值提高12.47%/6.26%，显式off/1024在8/16/24/36提高14.53%/14.51%/24.66%/8.45%。
c1的16/20/36线程提高30%–34%，但8线程下降18.85%；本报告保留这一限制。
源码、ELF、命令、环境及所有候选的原始结果保存在`bench/.tmp/hash-bold-20260927/`，
guest对应`/root/kdlock-evidence/hash-bold-*-20260927`。历史参照见
[上轮hash优化](20260927-hash-optimization.md)。

## 实现

1. 新增`kd_spin_runtime.c`，按`kd_exec.c → exe.c → kd_spinlock.c`组合编译。
   文件仍按职责维护，不复制实现，也不使用LTO。readiness、batch prepare/complete、
   frame bind/retire采用GNU always-inline，同时保留其他调用者的外部入口。
   编译器可在combiner循环内消除跨对象调用并专门化固定的单锁深度和batch lease。
2. clobber目录`KDWC001`用两个重叠32位加载精确比较，`KDAB`用一个32位加载。
   原七字节`memcmp`会形成每请求一次的函数调用；比较的字节范围没有扩大。
3. 普通clobber unlock的native字节路径不再建立C frame。只对此ABI壳允许尾调用，
   其他owner尾转到既有`kd_spin_unlock`；最后一个pin需要调度时，
   通过`static_call_mod(preempt_schedule)`尾转到内核导出的trampoline，保留原有preempt
   decrement/test与return thunk。动态抢占更新trampoline；模块不引用未导出的key。
   该入口单独按64字节对齐，避免相邻大函数的布局变化扰动native前缀。

准入、source OPEN及状态acquire、物理owner、COMPLETE/FULL区分、共享包寿命、
ACK及release唤醒顺序均保留；没有增加锁、全局热计数、逐请求时钟或运行期安全检查。
JIT翻译器、wrapper、预取距离与既有producer栈提示不变。本轮不是新的NUMA调度策略。
冻结源码/ELF审计确认35个正文/后端源码文件一致，三方workload运行section及其relocation一致，
仅阶段文件名、debug路径与build-id有差异；TCLock模块、allocator guard、client和daemon二进制相同。
最终combiner不再调用上述五个外部helper或`memcmp`，外部入口仍存在；native unlock共45字节，
无push/pop/call或RBP frame，scheduler尾调用元数据有效。这是静态指令证据，未测PMU/cache miss。

## 方法

固定2.5GHz，40个vCPU按编号固定到宿主0..39；worker顺序用0..35，collector用38。
20线程内位于node0，24及以上跨两个node。内核`6.1.159-kdclobber2`，Build ID
`5ca28058e156f34a2c7fe91e8e0fbf92f4e51960`，`nokaslr`、dynamic preemption=voluntary。
运行前确认`pre_static_boot_20260915`快照，宿主frequency/affinity保留前后核验。
没有编译或更换内核。

每个worker预热48000次；正式测量2秒，排除最初300ms，选至少300ms的完整cohort最高窗口。
每配置3轮；同时保留整段精确计数、全部窗口快照和每worker进度。
表中Mops/s均为峰值；`(max-min)/min`表示三轮全范围，不是置信区间。
ns/op取同一最高峰值窗口的elapsed/completed，不使用整段ns/op替代。
JIT计数属于整段测量，TCLock代理比例未测，不能把其记录中的占位0解释为没有代理。

## 候选过程

四组候选各36场，全部完成业务、IRQ/preempt检查及模块排空，离线重算144个峰值通过。
`unity`只有合并编译；`inline`增加四个helper强制内联及整数目录比较；二者使用off/1024。
`default`再内联readiness并采用kernel/512，暴露1/2线程回退。
`leaf`加入native unlock尾调用，回收大部分低线程损失，但出现新的scheduler分支objtool warning。
先用独立C helper消除新增warning，但低线程表现仍偏低。该中间候选的完整矩阵
在第71场排空后主动STOP（计划135场，64场未运行），其71场全部通过独立审计；
1线程范围11.980–11.993、2线程2.400–2.571 Mops/s，8线程仅完成两轮KD，不能视为完整三轮。
随后64字节对齐的18场候选中，1线程12.011–12.024、2线程2.414–2.666 Mops/s，收益混合。
最终通过编译器可见的module static-call尾调用直接省去helper frame。
两次中间构建失败分别是缺少static-call头文件、普通static-call引用未导出的key；
均保留原始失败日志，最终使用模块接口构建通过且没有新增unlock warning。
这些中间结果没有合并成最终成绩。
