# 2026-09-19：直接 API 三方性能对比

**150/150 场有效并正常排空，共完成 147000000 次操作。** 统一 hook、hotlock
发现和进程筛选已退出被测调用路径。20 线程时：1 cacheline 的 kdlock 吞吐为
Linux 的 66.9%、TCLock 的 77.9%；16 cacheline 时为 Linux 的 93.2%、TCLock
的 126.3%。这表明绕过入口策略后，kdlock 仍有明显固定成本；本次没有做阶段
计时或采样，不能进一步归因具体函数。

ns/op 是总 wall 时间除以全部线程的完成数，不是单次获取锁延迟。

  原内核、frame pointer 和缓解配置保持原样。guest CPU 0–19 都在 NUMA node 0；

  原有手写切栈函数的 objtool 栈告警仍存在，没有宣称解决栈展开问题。
- 基础检查、TCLock 切栈、clobber 寄存器破坏检查（含新直调壳）、20 个入口准入
