# 2026-09-23：恢复 C if 冷热分支

基于 `95d01f7`，将 `KD_SPIN_DIRECT_LOCK` 的整段汇编判断恢复为 C `if`。
取得一次 preempt pin 后读取已有 per-CPU `rate_hot`；冷分支普通 C 调用完整原生
CAS/pending/MCS，热分支复用 `KD_SPIN_DIRECT_CALL` 的 pinned clobber-v1 入口。
寄存器只由约束/clobber描述，不手写push/pop；编译器决定保存位置，允许保存出现在if前。
热continuation仍紧随CALL，解锁仍按锁字低字节5识别冷所有权，不重读热度。

冷路径的排队和采样逻辑原本已完整，本次保留。`spin_hot_min_queue`范围0..16、
默认4；0按原MCS发布采样，N>0时冷CPU在队头观察到至少N个已链接节点才计升温样本。
计数包含队头自身，不是线程数；CPU初始冷、每线程最多一个在途节点时，N=4可使
1/2/3线程保持冷态。已热CPU不会因线程数减少立即冷却，没有MCS事件时热值继续缓存。
spin每个合格事件检查400亿TSC窗口、单锁第33次检查25亿窗口，参数及默认开关均未改。

## 生成代码

冻结的 `caller-kdlock-cold-on.txt` 中，`sc_body_1` 的C gate位于`0x5a1..0x5bf`，
其中`0x5b3`直接GS读取。热CALL位于`0x5d9`、continuation为`0x5de`；
冷CALL位于`0x62b`，跳过SP/IP/BP准备。热分支在`0x5c8`保存后续使用的锁地址，
冷分支在普通CALL返回后`0x630`建立对应栈值。宏中没有手工寄存器适配区。

该GCC构建仍在函数序言`0x58d..0x595`保存RBX/R12–R15，未消除这五次保存。
因此不能把“恢复if”写成“本次已省掉五个寄存器”；本次仅恢复编译器按分支安排的自由。
