# 2026-09-22：512槽直接映射 spinlock 三方性能

> 已撤回：用户因性能下降要求恢复 `bf16b10` 的256桶/256记录实现。下文保留该实验当时的结果；[恢复后的验证](20260922-directhash-v2-rollback.md)单独记录。

本次运行当前工作树（`bf16b10` 加512槽直接映射改动），未修改执行代码。
仅测 Linux 原生、TCLock、当前 KD；未增加旧版 KD 测量臂。

## 环境与统计

guest `6.1.159-kdclobber2`，Build ID `5ca28058e156f34a2c7fe91e8e0fbf92f4e51960`，
voluntary、nokaslr；40个vCPU按编号固定到宿主CPU0..39，测量前后均核对。
各组用guest CPU0..T−1，对应同一宿主插槽0。内核、TCLock及协议设置沿用前次。

`cachelines=1,16`、`threads=1,4,8,16,20`、三后端、两轮，共60场；
每线程100000次，plain正文，observe固定准入，仍记录热度；不是adaptive性能。
单CPU48000次预热及JIT准备不计时，奇数轮后端逆序。每后端独立取有效最大吞吐，
ns/op取同一获选会话。保留所有两轮样本，不按快慢删样。

`Mops/s = completed × 1000 / wall_ns`，包含获取、正文、解锁、锁外工作及循环；
不是单独获取锁的延迟。KD/TCLock为两者各自最大吞吐之比。

TCLock未测代理次数，不将其未知执行量写为零。最终无worker/daemon/provider残留。

## 与已有记录的区别

本次20线程KD的c1/c16为3.916/3.831 Mops/s；修改前回退版历史值为5.197/4.809，
分别低约24.6%/20.3%。同期本次TCLock为5.103/3.228，之前为5.010/3.269。
这是相同配置与统计口径下的分批历史比较，未做同期交错旧版对照，不能据此确定
具体指令、布局或缓存机制的因果关系。直接映射减少操作数未表现为本轮吞吐提升。
源码保留用户要求的512槽版本，本次未执行自动回退或新增优化。

本轮没有重新跑独立单元、SELFTEST探针、nested/early、真实mutex JIT或PMU。
已有功能证据见[直接映射改动](20260922-directhash-v2.md)，不算本轮重跑。
