# Architecture

This document describes how kdlock works as written in this directory. It is
the reference for the code in `kernel/` and for the contract the translator in
`jit/` must meet. Status: nothing here has been booted or measured; see
[BUILD_AND_TEST.md](BUILD_AND_TEST.md).

## 1. Goal and mechanism

A contended lock is the place where the lock holder can do the waiters' work
cheaply: the protected data is already in its cache. TCLocks does this by
letting the holder (the *combiner*) switch its stack pointer to a waiter's
saved stack and run the waiter's critical section. It cannot do it for code
that depends on the running task (`current`, the stack canary, the top of
stack), because those are read through `%gs` and `%gs` still belongs to the
combiner.

kdlock keeps the TCLocks mechanism and changes what the combiner runs: not the
waiter's original code but a **relocated copy** generated by a userspace
translator. In the copy, the few task-identity accesses read the waiter's
values. Anything the copy cannot execute correctly ends it with an *exit*,
and the waiter then continues natively from exactly that instruction
(*handback*). Delegation is therefore always optional: a section that cannot
be delegated is simply run by its owner.

Terms: **origin** (W) is the task whose critical section is being run;
**executor** (C) is the CPU/task that runs it; the **session** is one
combiner's run over a queue; a **packet** (`struct kd_regs`) is the
continuation state of an origin; a **site** is the return address of a
lock call, i.e. one place in the kernel that takes a lock; an **image** is
the generated copy for one site.

## 2. Components

```
 kernel (built in, CONFIG_KDLOCK)                       userspace
 ┌───────────────────────────────────────────┐         ┌──────────────────────┐
 │ kd_entry.S   entry stubs, resume, jit      │         │ jit/kd_daemon.py     │
 │ kd_core.c    wait, session, executor       │ events  │  event loop          │
 │ kd_spinlock/rwlock/mutex/rwsem.c  families │───────► │  cumulative knowledge│
 │ kd_image.c   sites, images, event ring     │         │ jit/kdjit/translator │
 │ kd_dev.c     /dev/kdlock, debugfs stats    │◄─────── │  capstone, relocation│
 └───────────────────────────────────────────┘ images  │ jit/kdjit/kernel.py  │
                                                        └──────────────────────┘
```

* Kernel side is built into the kernel. It must be: generated code addresses
  per-CPU state with a 32-bit `%gs`-relative displacement, which only
  built-in per-CPU data permits, and the locks are used from early boot.
* The translator is a userspace program. It reads kernel text through
  `/dev/kdlock`, builds an image per site, asks the kernel for executable
  memory, links the image for that address and loads it. The kernel never
  waits for it.

## 3. Lock objects

All four families share one 4-byte queue word `struct kd_qlock`
(`locked` byte, `flags` byte, 16-bit MCS tail) and one set of queue
primitives in `kd_internal.h`.

| Object | Size | Layout |
| --- | ---: | --- |
| `struct kd_spinlock` | 4 | the queue word is the lock |
| `struct kd_rwlock` | 8 | qrwlock-style count (writer byte, writer-waiting bit, reader count) + queue word `wait` |
| `struct kd_mutex` | 32 | queue word (`locked` is the lock, flags `SLEEPERS`/`HANDOFF`), `wait_lock`, `owner`, `waiters` list |
| `struct kd_rwsem` | 40 | `count` (writer bit, waiting writer, need-wake, reader bias) + a `kd_mutex m` used as the queue |

The sizes equal the native ones, so containers that embed locks
(`struct page`, `lockref`, ...) keep their layout.

Queue nodes (`struct kd_node`, one cache line) live in per-CPU arrays:
spin-class nodes are a per-CPU LIFO stack (`nr_nodes`), sleepable-class nodes
are allocated from a FREE-state pool. Four nodes per CPU and class
(`KD_MAX_NODES`); when they run out the caller waits without queueing.
Node states: `FREE, WAIT, RUN, HEAD, RESUME, ABANDON`.

## 4. The contended acquisition, step by step

### 4.1 Entry stub (`kd_entry.S`)

Every delegable entry (`kd_spin_lock*`, `kd_write_lock*`, `kd_mutex_lock*`,
`kd_down_write*`) is an assembly stub, not a C function, so that it can see
and save the caller's registers.

1. **Fast path.** One cmpxchg on the lock word. On success it adjusts
   preempt count / IRQ / BH state as the native API would and returns. No
   packet, no stack switch.
2. **Slow path.** If `kd_cpu.busy` is already set (an interrupt on this CPU is
   inside a wait, or a session is running) or the CPU has no wait stack, the
   stub falls back to a plain, non-publishing wait (`kd_*_plain`). Otherwise
   it sets `busy` with a single non-locked `bts` (an interrupt on the same CPU
   sees it atomically) and stores the caller's continuation into this CPU's
   packet: callee-saved registers, `rsp`, return `rip`, flags. The return
   address is the *site*.
3. It switches `rsp` to the per-CPU **wait stack** (16 KiB) and calls the C
   wait function. From here the caller's own stack is untouched and unused:
   that is what lets another CPU run on it.

### 4.2 Waiting (`kd_core.c`: `kd_wait_spin`, `kd_wait_sleepable`)

The waiter looks its site up in a hash table (preemption off, no locking).

* Site has an image → queue a **delegable** node (`entry` = image entry,
  `regs` = packet).
* No image → queue a plain node, and count the contention; at 64 contended
  waits (`KD_REQ_THRESHOLD`) a `KD_EV_REQUEST` event asks the translator to
  build one.

The node is appended with one `xchg` on the queue tail. A node with a
predecessor spins on its own `state`:

* `RESUME` — a combiner already executed this waiter's section; the waiter
  returns `KD_WAIT_RESUMED`.
* `HEAD` — it is now the queue head: it takes the lock itself.

### 4.3 The queue head becomes the combiner

The head takes the lock (`kd_q_head_lock`), runs the family's `post()` hook
(rwlock: wait for readers; rwsem: set the writer bit and wait for readers),
then runs a **session** (`kd_session`):

```
while the next node n exists and the budget is not exhausted:
    stop if n has no image, need_resched(), or the mutex HANDOFF flag is set
    if NUMA order is on and n is on another node: defer it (see 7)
    stop if n's saved interrupt state is incompatible with ours
    sleepable class: claim n with WAIT -> RUN; if the waiter withdrew, free it
    prefetch the next waiter's packet and stack
    done = kd_exec_one(root, n)          # run n's section, section 5
    unlink n from the queue
    publish n.state = RESUME              # last access to n and its packet
    stop if the section was handed back (done == false)
```

After the session the head runs the family's `release()` hook if the queue
word is only a wait lock for that family, promotes its successor
(`kd_q_pass`) and returns `KD_WAIT_LOCAL`: the stub then lets the head run
**its own** critical section natively. Because the head took the lock before
the session and keeps it throughout, the order of sections is: delegated
waiters first, its own last.

### 4.4 Waiter resume

On `KD_WAIT_RESUMED` the stub calls `kd_finish_resume(pin)`: it disables
interrupts, applies the preempt-count change the section caused
(`pc_delta`) and installs the packet's logical registers and flags with
`kd_resume`, which switches back to the original stack and returns to the
instruction **after the section's release call**. The origin never runs the
section and never executes the release.

## 5. Running a section (`kd_exec_one`)

The executor prepares and enters generated code:

1. `local_irq_save`; if the origin had softirqs off, BH off as well.
2. Add `KD_EXEC_PIN` (32) to the preempt count. A section may release locks
   the origin took earlier (nested, non-LIFO); the pin keeps the count from
   reaching zero on the executor.
3. Fill `kd_cpu`: `task` (origin), `canary`, `stack_top`, `root` (the lock
   being served), `cur` (the packet), `anc` (number of outer roots).
4. `kd_jit_enter(packet, entry)` loads the packet's registers, installs the
   origin's logical flags with `popfq`, switches `rsp` to the origin's stack
   and jumps into the image. Execution is real machine code on the origin's
   real stack.

The image leaves through an **exit stub** (`mov` only, to
`gs:[kd_cpu.exit_ip / resume / exit_code / aux]`, then `jmp kd_jit_exit`).
`kd_jit_exit` saves the full state back into the packet and returns to
`kd_exec_one`, which decides by exit kind:

| Exit | Meaning | Action |
| --- | --- | --- |
| `UNLOCK` | the section called the release of the **session root** | do not release; record its effects on the origin (`kd_apply_unlock`: preempt count, IF, BH) in the packet; the section is complete (`KD_STOP_DONE`) |
| `UNLOCK_ANC` | release of a non-root lock while outer sessions exist | if the lock is an outer root: mark `released`; else perform the release natively and continue |
| `NESTED` | a contended inner spin-class lock inside the section | acquire it recursively (section 8) |
| `ACQUIRE` | a sleeping-family acquire (mutex, rwsem) inside the section | try to take it as the origin without sleeping; else hand back |
| `MISS_CODE / MISS_IND / MISS_RET` | unknown direct target / indirect target / return target | report to the translator, hand back |
| `FRONTIER` | instruction or callee only the origin can run (extable instruction, privileged instruction, scheduler entry, user copy, unknown text) | hand back |
| `BUDGET` | translator budget exhausted | hand back |

Afterwards the executor measures the preempt-count delta, subtracts it from
itself and adds it to the packet (`pc_delta`), restores IF/BH, and returns.

### Handback

The packet holds the first instruction the executor did **not** execute. The
lock word stays "held" and now **belongs to the origin**: the combiner does not
release it. The node is resumed, the origin continues natively from the exit
point (every effect of the executed prefix stays, nothing is replayed), and
later releases the lock with the ordinary unlock. The combiner goes back to
waiting for the lock as queue head. No extra lock states exist; handback is a
plain ownership transfer, which is why it is cheap and exact.

Families where the queue word is only a wait lock (`keeps_q`: rwlock, rwsem)
transfer the grant (writer byte / writer bit) but not the queue word; the head
keeps the queue word and continues its session after reacquiring the grant.

## 6. Context transfer

While a section runs on the executor:

* **Task identity.** Accesses to `current_task`, `__stack_chk_guard` and
  `cpu_current_top_of_stack` read `kd_cpu.{task,canary,stack_top}`. These are
  the only `%gs` accesses the translator rewrites. All other per-CPU accesses
  address the executor's own per-CPU area (see
  [DIFFERENCES.md](DIFFERENCES.md) D3).
* **Interrupt flag.** The executor installs the origin's logical IF with
  `popfq` on entry and reads it back with `pushfq` at the end. The executor
  never enables interrupts it had itself disabled: sections whose saved IF is
  on are not run by an executor that has interrupts off (`kd_ctx_compatible`).
* **Preemption.** Disabled for the whole section. The change in preempt count
  the section causes on the executor (including the lock it ends with) is
  undone locally and added to the origin on resume.
* **Logical task for lock functions.** Native lock functions called from a
  section (`kd_*`) act for the origin through `kd_logical_current()`: mutex
  owner, wake targets, etc.

## 7. NUMA order

As in TCLocks, a session serves only waiters of the combiner's NUMA node
(`node_id` of the CPU that queued the node). A delegable waiter of another
node is unlinked, still waiting, onto a session-private list, and the session
continues with the waiters behind it. At the end the list is spliced back
*in front of* the queue in its original order, so its first waiter is the next
head and combines for its own node. Passed-over waiters count against the
batch budget (`kd_batch`, default 1024) so handbacks cannot extend it;
waiters without an image are never passed over. `kd_numa=0` restores FIFO.

Consequence: a waiter is delayed by at most (batch × number of nodes ahead of
it) executions. This is a bound on batches, not a fairness guarantee for
arbitrary workloads.

## 8. Nesting

When the section a combiner C_A is running for W meets a **contended** inner
lock B, C_A behaves like a TCLocks combiner: it becomes the waiter for B and
publishes the continuation it is running.

* Spin-class locks (spinlock, rwlock writer) have `_jit` entries (generated
  code calls these instead of the public ones). The fast path is identical.
  On contention `kd_nested_exit` stores the continuation (callee-saved
  registers, `rdi`, `rax`, `rsp`, flags) into **the current packet** — the
  same packet, no copy — sets `resume` to the generated-code address after the
  call, and returns to the executor with exit `NESTED`.
* The executor queues a node for B that points at that packet and the
  generated code after the lock call (`kd_spin_nested`, `kd_write_nested`,
  `kd_mutex_nested`, `kd_down_write_nested`). B's queue decides:
  1. B's combiner C_B claims the node and runs W's continuation onwards. At
     `unlock(B)`, C_A's node is resumed and C_A continues W's section in
     generated code from the state C_B left.
  2. C_A reaches the head of B's queue: it takes B, serves B's other waiters as
     a nested session (depth-limited), and continues W's section.
  3. B is a mutex/rwsem and waiting would require sleeping: W gets the
     continuation back with the call to B still pending (handback).
* The packet records the locks it is being executed for (`roots[]`, at most
  `KD_MAX_ROOTS` = 4, with `nroots`). If an inner executor meets the release of
  an outer root (`lock(A); lock(B); unlock(A); ...; unlock(B)`) it must not
  unlock it, because A is still held by C_A's session: it sets a bit in
  `released` and applies only the logical effects. C_A sees the bit when its
  node resumes and ends W's turn on A. To keep ordinary releases free of this
  check, generated code compares only against `kd_cpu.root`, and leaves
  generated code for a non-root release only when `kd_cpu.anc` (the number of
  outer roots) is nonzero.
* A handback from an inner executor propagates outwards through the node
  states: each level either keeps its lock (its root was already released) or
  passes it to W, and W resumes natively exactly once.

Bounds: `KD_MAX_ROOTS` = 4 session locks per continuation, `KD_MAX_DEPTH` = 3
open sessions per CPU. Beyond them the inner lock is only waited for (no
publication). The recursion runs on the combiner's wait stack, which is
sized for it; real stack use has not been measured.

## 9. Images and sites

* One immutable image per site, replaced whole. A site is the return address
  of a lock call; it is looked up with preemption off in a hash table of
  `1 << 10` buckets.
* Publication: the translator asks `KD_IOC_IMAGE_ALLOC` for executable memory
  (`execmem_alloc` + `set_memory_rox`), links the image for that address and
  loads it (`KD_IOC_IMAGE_LOAD`). The new site entry replaces the old one; the
  old image is freed after `synchronize_rcu()`. A waiter and a combiner are
  non-preemptible from lookup to resume, which is what makes RCU enough: no
  reference counts.
* Learning: each image has 64 learning reports (`KD_MISS_BUDGET`). A miss or
  frontier exit reports `ip`/`target` into a lossy 4096-entry event ring that
  the daemon polls.
* Usefulness: every 256 executions (`KD_SITE_WINDOW`) a site whose sections
  were mostly handed back is switched off (`KD_EV_SITE_OFF`) until a new image
  arrives.
* `KD_IOC_ENABLE` is the global switch (static key `kd_delegation`). With
  delegation off every lock behaves as a plain queued lock.
* Text lifetime: an image copies text and embeds its addresses. A module
  notifier increments a text generation on module load and, when module
  text or init text is about to disappear, unpublishes every site, waits one
  grace period, frees all images and reports `KD_EV_TEXT_GONE`. A load
  carries the generation its image was built from and is refused if it
  changed, and a site must lie in live text. Fixup instructions are reported
  per text region (core or module) by `KD_IOC_TEXT`, so module exception
  tables are covered.

## 10. Invariants the code relies on

1. Exactly one participant advances a packet at a time: the origin before it
   queues, the combiner while the node is claimed, the origin again after
   `RESUME`. `RESUME` is the last access to the node and to the packet.
2. A queued waiter is non-preemptible and on its wait stack until resumed, so
   its node, packet and stack outlive every access by a combiner.
3. Handback never replays: the packet always names the next instruction to
   execute.
4. A combiner never sleeps in a delegated section; every call that can sleep
   is a frontier exit.
5. Lock word ownership is by value: after a handback the origin's ordinary
   unlock is the only way the lock is released.
6. `kd_cpu.busy` is set for the whole time a CPU's packet and wait stack are
   in use; interrupts that find it set wait without publishing.

## 11. Known limits

See also [DIFFERENCES.md](DIFFERENCES.md).

1. **Partly tested.** Boot, all four families with and without delegation,
   two-level nesting, handback through frontier and sleeping-acquire exits,
   module unload with live images: see [BUILD_AND_TEST.md](BUILD_AND_TEST.md)
   section 5. Deeper nesting, interrupt-context interactions, signals and
   hotplug are not tested.
2. **Handback inside a per-CPU-bound region.** If a section is handed back
   while it has preemption disabled beyond its locks (counted as
   `handback_pinned`), the origin continues on a different CPU than the code
   before the exit ran on. The preempt count is transferred; per-CPU pointers
   already taken are not.
3. **Flags across call/ret.** Return and indirect-branch dispatch clobber
   flags; the System V rule that flags are dead there is assumed.
4. **Text patching.** Images are built from live text. Later jump-label,
   static-call, ftrace or livepatch changes are not tracked.
5. **Module load/unload drops every image.** Correct but coarse: each
   module unload (and each module's init completion) causes all sites to be
   translated again.
6. **Unwinding.** No ORC data for images, the wait stack or the stack switch;
   stack traces through them stop early.
8. **Not delegated:** readers, trylocks, `raw_spinlock_t`, waiters in
   interrupt context. Native code called from a section that itself blocks on
   a lock waits without publishing.
9. **Nesting bounds** as in section 8; a release reached through a sibling
   `jmp` in a nested run is handed back.
10. **API coverage:** see [KERNEL_INTEGRATION.md](KERNEL_INTEGRATION.md).
