# Managed killable rwsem mechanism fixture

This fixture exercises private typed rwsem acquisition and cancellation. It compiled and signed for kernel8 from snapshot `140aecc4`. An initial attempt completed the three cold cases, then failed at source-span selection before constructing an image. Its separate ordinary recovery completed. A second attempt using the corrected named spans published an image and reached the first learning scene, then timed out waiting for W's actual exit while the fixture withheld C's exit ACK. That attempt remains `failed_retained`, with cleanup pending. The grouped exit-ACK correction below is source-only and unvalidated. Complete generated-case validation remains pending. This fixture does not execute mmap or replace real syscall validation. It binds with `source_calls=false`, so its ordinary Linux killable calls remain callable/native. The separate global source opt-in is not used here. No performance, full C-function generated return, arbitrary nested killable wait or general support claim follows from the build. Its actual process exit then exercises the managed exit hook.

The runner uses real `fork`, deliberate scene-specific `SIGKILL`, and bounded `waitpid(WNOHANG)` observations. A kernel `done` flag is never a task-exit witness. Signals are sent only after the required actual queue/control predicate. Deadlines report failure and retain the controller, transport and original actors. Proxy learning and completion scenes separate exit permission from actual exit. After W's native helper is released, every requested C/W participant, and D when present, must report its expected API result, once-only effects and helper return. The runner joins W's exact synchronous release request, handling, physical completion and typed native unlock. It saves all participant status and the immutable raw event prefix before any exit ACK. The cold queued-exit case keeps its original single-role ACK and actual W exit before H is released.

The cases cover the following distinct outcomes.

- An immediately available root grant wins over an already pending fatal signal, returns zero, and performs its body and helper effects once.
- A local MCS head waiting for an existing reader returns `-EINTR` without a grant or body effect. The original reader remains held until its own release.
- A queued caller returns `-EINTR` and actually exits while H still holds the predecessor writer. Queue retirement and slot freeing occur only after H's actual release. Exact native source-scope membership remains live before that release and ends after allocation finalization.
- A canceled native head passes an empty MCS turn while R remains held. C then claims root W and registers as its foreign physical waiter. W's fatal signal reaches C without waiting for R's release, and W receives no grant or body execution.
- A killable C is canceled while serving a currently granted W. Its error waits for W's physical completion. It takes no further outer cohort member and does not requeue. D continues through the existing MCS queue.

The last case separately proves D's grant belongs to a physical owner other than canceled C. Training scenes use the same ordinary source body without canceling C.
