The three notes are preserved byte-for-byte as historical source-review inputs. The native-prefix note's last paragraph says to “prevent” W handback while physical duties remain open. This is **not permission to delay the existing immediate first-unexecuted handback rule**. The authoritative custody refinement states the missing obligation: before admitting a native context effect on physical C, there must be a legal route for native W to execute its exact suffix through the matching release while C retains its duty. Native PTL pins C, so a W confined to C's occupied CPU cannot progress through a C busy loop. Executing W elsewhere still needs exact native release routing and ACK plus W-local context admission. If that route is unavailable, decline before the context effect. Delayed handback, early unlock/reacquire and a new mixed-context progress policy are not selected.
