# Kernel 8 provider ioctl frame build

The `0798c1ab` metadata provider compiled and signed successfully. All nine
actual commands returned 0, and the build recorded no warnings. The two bounded
`jit_ioctl` disassemblies measure a fixed entry RSP reservation of 1,912 bytes
in the previous provider and 704 bytes in the new provider. Each has 48 bytes of
preceding callee-save pushes, giving entry-prologue consumption of 1,960 and
752 bytes respectively. These figures exclude the return word and called
functions. They establish neither a complete control-path stack bound nor AUX,
scheduler, IRQ or generated-execution compatibility.

The provider was not loaded, and no MM syscall or JIT body executed in this
lane. The earlier provider's warning remains unchanged in its separate
[provider and AST record](../kernel8-provider-build-runner-ast-20261111/README.md).
No earlier failure or runtime result is replaced by this build.

## Measured ioctl entry change

| Measurement | Prior de76 provider | New 0798 provider |
| --- | --- | --- |
| Fixed RSP reservation | 1,912 bytes (`sub rsp,0x778`) | 704 bytes (`sub rsp,0x2c0`) |
| Callee-save pushes | 48 bytes | 48 bytes |
| Entry prologue, excluding return word and callees | 1,960 bytes | 752 bytes |
| Build diagnostics | One 1,912 > 1,024 frame warning | None |

The entry reduction is 1,208 bytes. It is a compiler-output observation for
these exact two modules, not a claim that the whole call chain shrank by that
amount. In particular, a called constructor's frame is outside this measurement.
Both raw logs are retained, with SHA-256
`ca6699e40df85d85c04f5f05b3517d1c9cd1ad343dc0d317099ddeeb1bc1a2b8`
(old) and `b9d67f2215e95ac691b73a952cadde76354ec436074191f77cdf5cf4afc27f88`
(new). The offline ELF audit independently matches each exact SUB and all six
push instructions to the respective unsigned module bytes.

The source change captures the sole ABI2 ioctl request in per-call cold
backing, moves the zero-config comparator to immutable static storage, and
frees that backing on every validation, operation and reply-copy path. The
existing reply copy after operation failure and the control mutex order remain.
No retained source/runtime object stores the per-call request pointer. This
build does not execute those input/error/retirement paths.

The previous result `21d6d90b4d2c91ab2760a0319d5eef8933148ab6452cf1a3f523d2b98b8c63cf`
retains its original warning and source `de76da8a`. Its exact module bytes,
