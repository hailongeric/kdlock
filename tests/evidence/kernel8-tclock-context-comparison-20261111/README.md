TCLock saves six native callee-saved registers and changes hardware RSP to a waiter's saved native continuation. Its switch does not switch the Linux task, GS base or CR3. Physical C remains the executor while using W's stack. The current KD wrapper keeps C's hardware stack active and represents W's source SP, BP and registers in the original mapping and one canonical packet. An unsupported source continuation is returned to actual W. [Detailed source comparison](comparison.md)

A task-owned auxiliary wait stack supplies disjoint control storage. It does not supply another schedulable task or CPU. If C is nonpreemptible on the only CPU on which W can run, selecting another stack cannot schedule W. The proposed retained-C/immediate-W route would need independent physical W execution during C's nonpreemptible interval. It may reuse the existing W Linux task and stack. An extra Linux task or stack is not inherently required. CPU admission/reservation and exact native paired service records are unimplemented, and this comparison does not approve that proposal. Native borrowed-body execution is a different prospective policy. [Detailed source comparison](comparison.md)

The existing K fixture inputs provide 65,536 auxiliary bytes and sixteen slot/frame pairs per task, in addition to the retained original stack, core, source and image duties. These are existing capacity parameters, not measured overhead or CPU capacity. No new record layout, count or exact incremental byte cost has been selected. [Parameter witness and scope](audit.json)

The source review also distinguishes logical W current-task mapping, W's captured origin GS and physical C's scheduler, preemption and RCU context. Same-mm or common-CPU placement alone establishes neither complete context equivalence nor progress. Existing safe handback before an unsupported native context effect remains in force. The five-span MM proposal stays paused with AUXILIARY_CONTEXT unset. [Detailed source comparison](comparison.md), [separate emitted kernel8 context review](../kernel8-mm-context-review-20261111/README.md)

Native W context, GS/RCU equivalence and callback-return lifetimes for any proposed new route remain unproved. Exact owner, source-stack, canonical-state, image, request, callback and auxiliary-control lifetimes remain required. The note identifies missing native spin/RCU release and ACK integration without treating a stack switch or task pointer as proof of those lifetimes. Pinned upstream behavior and the local Linux 7 comparison-port restrictions are labeled separately. [Detailed source comparison](comparison.md)
