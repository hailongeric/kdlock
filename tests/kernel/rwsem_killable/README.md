# Managed killable rwsem mechanism fixture

This source-only fixture exercises private typed rwsem acquisition and cancellation. It has not been compiled or run. It does not execute mmap or replace real syscall validation. This fixture binds with `source_calls=false`, so its ordinary Linux killable calls remain callable/native. The separate global source opt-in is not used here. No performance, full C-function generated return, arbitrary nested killable wait or general support claim follows from these sources.

`payload/fixture.c` binds a private Linux rwsem to one KD gate and a cold finite native pool with `source_calls=false`. Native H/R holders use ordinary callable Linux APIs. Managed child RUN ioctls enroll the actual calling task before invoking the private source body. No kernel worker impersonates the original requester. The child returns through its own native continuation and does not explicitly leave the runtime. RUN remains stopped after body return until a parent exit ACK. That gate retains the actual current endpoint for metadata snapshots. The original task clears its raw storage observer before returning to userspace. Its actual process exit then exercises the managed exit hook.

The runner uses real `fork`, deliberate scene-specific `SIGKILL`, and bounded `waitpid(WNOHANG)` observations. A kernel `done` flag is never a task-exit witness. Signals are sent only after the required actual queue/control predicate. Deadlines report failure and retain the controller, transport and original actors. A failure does not release gates, kill remaining actors, unload, settle records or replay a body. Control devices precede composition and report `setup_error` plus exact retained roles. RUN stays closed on any construction error. A failed constructor with a non-NULL runtime remains queryable without a guessed destroy. Clean NULL failures use checked ordinary unwind, and an unwind refusal preserves every remaining role for RETIRE. Later recovery requires its own reviewed ordinary cleanup.

The cases cover the following distinct outcomes.

- An immediately available root grant wins over an already pending fatal signal, returns zero, and performs its body and helper effects once.
- A local MCS head waiting for an existing reader returns `-EINTR` without a grant or body effect. The original reader remains held until its own release.
- A queued caller returns `-EINTR` and actually exits while H still holds the predecessor writer. Queue retirement and slot freeing occur only after H's actual release. Exact native source-scope membership remains live before that release and ends after allocation finalization.
- A canceled native head passes an empty MCS turn while R remains held. C then claims root W and registers as its foreign physical waiter. W's fatal signal reaches C without waiting for R's release, and W receives no grant or body execution.
- A killable C is canceled while serving a currently granted W. Its error waits for W's physical completion. It takes no further outer cohort member and does not requeue. D continues through the existing MCS queue.

The last case separately proves D's grant belongs to a physical owner other than canceled C. Training scenes use the same ordinary source body without canceling C. Exact byte-based source scanning, GNU image construction, cumulative ordinary target learning, publication and coverage ACK use the existing compiler/session machinery. Training is bounded by an explicit pass count. Completion scenes retain a fixed published image and permit no new fact key or replacement publication.

The C-function epilogue remains outside protected generated completion.

The collector only copies preallocated 20-word scalar records. It grants no execution or release authority. Controller metadata snapshots use the RUN caller's retained storage scope while the enclosing ioctl prevents another acquisition or exit. They do not read source register contents. The wrapper clears its raw storage observer under the same mutex before returning to userspace. Post-exit checks use only saved identities, task references and actual event records.
