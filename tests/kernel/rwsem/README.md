# Reader-family mechanism fixtures

The rwsem and rwlock leaf modules reuse the ordinary fixture's actual source provider, compiler channel, image publication, task lifecycle and scalar observations. The rwsem runtime selects `KD_LOCK_FAMILY_RWSEM`. The rwlock runtime selects `KD_LOCK_FAMILY_RWLOCK` and uses IRQ-enabled atomic task context. Source operations call the family-prefixed public APIs. The existing mutex and spin runner entrypoints remain available as regressions.

The new sources are unexecuted. Build, syntax checks and behavioral runs belong in the designated VM after the complete core/fixture source review. Keep source and module output separate through the target kernel's `M`/`MO` interfaces. Caller-supplied source, event, transport and control limits are recorded by the shared runner. [Shared runner](../run_runtime_fixture.py)

Run `run_rwsem_runtime_fixture.py` or the rwlock sibling with the shared runner's exact kernel, GS, immutable-source and auxiliary-context arguments. Both new families require `--holder-timeout-ms` and `--runtime-block-visits`. Rwsem also requires finite `--coordination-spins` for its source-level reader probe. Rwlock requires five distinct worker CPUs through `--role-cpus` (the existing `--spin-cpus` spelling also works) and a separate `--controller-cpu`. Supply bounds sufficient for the declared finite fixture. No deployment defaults or request-exhaustion route are added. [Rwlock entrypoint](../rwlock/run_rwlock_runtime_fixture.py)

Native scenes check concurrent real reader credits, writer exclusion in both arrival orders, and local real rwsem downgrade. A repeated-read case uses one object with two real READ acquisitions and no pending writer, then checks latest-open exact release. Other nesting uses distinct A/B objects. Writer/read, read/write and read/read bodies use one canonical source state and separate mode/acquisition records.

The shared-B case checks that ordinary `up_read(B)` resumes the enclosing A proxy. The same-grant rwsem downgrade cases keep physical write authority through matching `up_read`, then verify the exact native W continuation. The nested writer-B case keeps ancestor A's physical duty retained during terminal propagation. Deliberate ordinary misses verify once-staged CALL effects and exact native read release. The fixed-image checks and miss archival remain separate stages. No rwlock downgrade API is introduced. [Reader assertions](reader_cases.py), [private source bodies and native scenes](payload/reader_cases.inc)

Reader admission may linearize inside the physical release callback. The assertions require its matching release request and callback begin, and separately require complete physical ACK before accepted retained `up_read`. Exact reader users and writer controls are joined through final slot retirement. Unexpected source frontiers, failed checks and timeouts preserve the actual fixture/control state for explicit ordinary recovery. The fixture remains synthetic kernel mechanism evidence, with the unprotected C epilogue native and general progress, performance and broader API/configuration support outside its scope.
